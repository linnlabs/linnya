# Governance

Linnya is an open-source project led and maintained by BCAutumn under the `linnlabs` GitHub organization. It is not presented as a company-run foundation, and maintenance capacity is intentionally lightweight.

## Decision making

- The lead maintainer has final responsibility for product direction, repository scope, releases, security response, and merge decisions.
- Domain and package owners may review changes within their established boundaries.
- Significant public contract, architecture, compatibility, security, or product changes should be discussed in a public issue or pull request before implementation, then written back to the owning stable documentation.
- Technical decisions favor clear ownership, low coupling, reproducible evidence, and long-term maintenance cost.

Community input is welcome, but opening an issue or pull request does not guarantee adoption or a schedule. A change may be declined because it conflicts with product direction, expands support obligations, weakens boundaries, or costs more to maintain than the project can sustain.

## Releases

Changes merge continuously when ready. Product releases are maintainer-approved snapshots with their own version, release notes, artifact verification, and platform checks; merge activity does not by itself create a release.

## Changes to governance

The lead maintainer may update this model as the contributor base grows. Material governance changes should be recorded in this file rather than inferred from informal discussions.

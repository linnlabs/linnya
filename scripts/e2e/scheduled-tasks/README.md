# 定时任务界面验收

`pnpm exec tsx scripts/e2e/scheduled-tasks/ui.acceptance.mjs` 在隔离探针里开启定时器（`--scheduled-tasks`），用 `chatFixture.mjs` 的本机回环 OpenAI-compatible 端点代替模型服务，不需要服务商密钥。所有操作走真实点击，只读取 preload 的定时任务接口做断言；读不到合法结果直接失败，不把接口错误当成“没有记录”。

覆盖：界面新建任务（选模型与档位）；立即运行写入记录、侧栏折叠行未读与前台提示；暂停与恢复；运行中删除任务时确认框说明正在运行并可一并停止，勾选后被挂起的模型请求确实被断开；设置页降低全局档位时提示受影响的定时任务数并可一起调低；删除模型的确认框说明有定时任务在用。

时间边界用开发态注入的时钟与时区（`--scheduled-tasks-clock`、`--scheduled-tasks-timezone` 与 `probe scheduled-clock`），每类一个独立实例：

- 以 1997 年启动：横幅写明系统显示的日期，不按时运行，“立即运行”仍能完成；恢复系统时间后横幅自动消失，不会逐个补跑 29 年的时段。
- 上海换到伦敦：下次运行按伦敦的 09:00 重算。
- 时钟前跳 2 年：只补跑最近一次，更早的时段合并成一条“超出补跑窗口”的跳过记录，运行记录里显示“共 N 次”。改时区与拨钟分两步做：同一步里换时区会按“东飞跳过的时段不补跑”处理。

注入时钟只在源码开发会话生效，不能代替在真机上改系统时间；Windows 的时区与主板时钟重置只由单元与集成测试覆盖。

# Security Policy

## Supported versions

Before the first stable release, security fixes target the latest source on `main` and the latest published desktop build when a fix can be safely shipped. Older development snapshots are not supported branches.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for `linnlabs/linnya` when it is available. Include affected versions, impact, reproduction steps, and any proposed mitigation.

If private reporting is unavailable, open a minimal issue requesting a private contact channel. Do not include exploit code, credentials, personal data, or sensitive infrastructure details in a public issue.

Please do not test against data or systems you do not own or have permission to use. The maintainer will acknowledge actionable reports when capacity permits, investigate them, and coordinate disclosure after a fix or mitigation exists. This project does not promise a fixed response-time SLA or bug bounty.

## Scope

Security reports include desktop privilege boundaries, command approval bypasses, plugin trust or signature bypasses, secret exposure, unsafe update behavior, and unauthorized data access. Ordinary bugs and feature requests belong in GitHub Issues.

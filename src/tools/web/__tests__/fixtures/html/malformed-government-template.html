浏览器可容错的政策正文

第一条，标准 HTML 解析器应当把提前关闭根元素之后的正文重新归入唯一的文档主体，并保留原有内容顺序。这段文字用于模拟公开政策页面的正文候选结构。

第二条，正文抽取器只能在规范化文档上运行，不能依赖第二个主体元素、文档根外节点或者站点专用的字符串修补。这段文字包含足够信息用于稳定候选评分。

第三条，页面能够被浏览器正常打开时，本地读取器不应因为轻量 DOM 适配器与浏览器建树规则不同而失败。规范化属于 Web Read 抽取边界自己的职责。

第四条，如果规范化失败，系统应返回稳定的领域错误事实，并根据失败阶段决定是否使用具有独立恢复价值的浏览器渲染，而不是泄漏第三方库异常。

第五条，如果 Readability 失败但语义主区域已经取得正文，应保留语义正文并标记抽取警告，不得让可替换增强抽取器推翻已经成功取得的内容。

第六条，如果规范化文档上的正文抽取仍然失败，系统应直接进入外部增强解析，不应在 Chromium 返回的文档上机械重复同一个抽取器。

第七条，未知代码异常仍然属于 provider error，不能通过扩大自动升级范围来掩盖实现错误。只有明确的抽取失败类型才能进入既定恢复阶梯。

第八条，缓存身份、结构化日志和工具错误文本必须同步新抽取语义，确保历史结果自然失效，并让 Agent 看到可行动而稳定的失败说明。

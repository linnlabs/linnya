# 语义层：标签与字段

本 domain 拥有工作区级的**标签**与**字段**定义，以及对象上的标签和字段值。对用户只有一个词“标签”：标签可以带字段，
比如“论文”带“作者”“年份”“已读”；给文档打上“论文”后，这些字段出现在它的属性里。正文和输入框里用 `@` 插入的是
[引用](../document-references/README.md)，与标签无关。

## 负责与不负责

- 负责：标签、字段定义；对象的标签与值；值的校验与空值合同；对象版本与恢复；标签与字段本身的改动（改名、合并、删除、改类型、改选项）及整批撤回；查询描述与编译；向[行动账本](../action-ledger/README.md)登记改动。
- 不负责：界面、保存的筛选（改动时由 [Host 的标签管理](../../app-hosts/linnya/application/semantic-schema/README.md)在同一事务里改写）、关系字段（随来龙去脉的关系表一起做）。命令行入口在 [Shell 内建 CLI](../../app-hosts/linnya/application/core-cli/README.md)，给 Agent 看的 `read_file` 属性段在 [文档属性段](../../app-hosts/linnya/application/document-properties/README.md)。
- 插件不能直接读写这些表，只能经 Host 端口。只读端口 `@plugin/backend/semanticTags`（`infrastructure/sqlite/semanticTagProjection.ts`）给插件列出标签、按 ID 读当前名称、按名称解析。插件在自己内容里存的标签 ID 不进 `semantic_object_tags`：合并后由端口按未撤回的合并记录跟到目标，删除后不再返回；删除、合并的影响预览只统计文档，不含插件内容里的引用。

## 对象 =（种类，ID）

标签和值挂在（种类，ID）上。种类由 Core 登记：`document`（`workspace_nodes.id`）第一版开放；`conversation`
（`conversations.conversation_id`）表结构已接受，读写入口暂不开放。插件不能新增种类；文档内的部分（如画布卡片）
仍按“文档 ID + 部分”处理，不算新种类。

每种对象各有一列外键（`document_id`、`conversation_id`），只有与种类相符的那一列有值。文档或对话被物理删除时，
无论经回收站清空、项目删除还是其他路径，标签、值与版本都随之级联删除，不靠各 owner 记得调用清理。
移入回收站时保留。新增种类时加一列外键并扩展 CHECK。

## 定义

- 标签与字段都是工作区级的，各有稳定 ID，可软删除。新建标签时记下是谁建的（种类、对话、Agent），迁移前建的没有记录。
- 名称先做 NFKC 归一化、合并空白，再做大小写折叠，结果在未删除的定义里唯一。折叠在 JS 里做：SQLite 的
  `lower()` 只折叠 ASCII。名称最多 64 字，不能以 `#` 或 `@` 开头。
- 新建前程序先查相近名称：去掉空格、连字符、下划线后相同，一方包含另一方（两字以上），或编辑距离很小（短名 1、
  六字以上 2）。有相近名称时拒绝并列出候选（`similar_name`），调用方确认不是同一个后传 `allowSimilar`。
- 字段类型：文本、数字、日期、日期时间、勾选、单选、多选、网址。单选、多选的选项有稳定 ID，值存选项 ID，
  选项改名不用改值；写入时可传选项名或 ID。
- 含 `.` 的字段名留给插件声明的字段（如 `slides.pageCount`）。插件字段记 `owner_plugin_id`，用户和 Agent
  不能写；插件声明与写入端口在第一个插件需要时接入。
- 一个对象可以有多个标签，不做继承。

## 字段跟随标签

对象的字段 = 它全部标签所带字段的并集，按打标签的先后与标签内字段顺序排列；多个标签共用同一字段时只出现一次。
字段列表是实时算出的，标签增删字段不迁移数据。

- 打标签时，新标签字段的默认值只在对象还没有该值时写一次。
- 去掉标签后，它带来的字段不再显示，值仍保留；重新打上即恢复。
- 只能写对象当前字段里的值；写别的字段报 `field_not_available` 或 `unknown_property`，并列出可用字段。

## 空值合同

读写与以后的筛选共用同一套含义：

| 写入 | 存储 | 读取 | 筛选“为空” |
|---|---|---|---|
| `null` | 没有这个键 | 不出现 | 是 |
| 空字符串（文本、网址、单选） | 没有这个键 | 不出现 | 是 |
| 空列表（多选） | 没有这个键 | 不出现 | 是 |
| 勾选 `false` | `false` | `false` | 否；筛选“未勾选”同时包含 `false` 与未设置 |

存储里不会出现 `""` 或 `[]`，“为空”只需判断键不存在。

日期存本地日历日 `YYYY-MM-DD`，按字面比较，不随时区变化；日期时间必须带时区（`Z` 或 `±hh:mm`），存原样字符串。
只存本地钟面时间会在换时区后落到另一天。

## 写入、版本与账本

- 每个写入是一个事务；在 owner 已有的事务里调用时随外层一起提交或回滚。
- 写对象必须给期望版本（`expectedRevision`，从未写过为 0），不符时报 `revision_conflict` 并给出当前版本。
  没有实际变化的写入不加版本、不入账。
- 文档必须在调用方的项目内、不在回收站，文件夹不能打标签。
- 每次写入在 `semantic_object_versions` 留一份标签与值的快照，每个对象保留最近 50 个版本，供按运行撤回。
- 入口绑定了执行者时，写入在同一事务里向账本登记一条细账：动作 `tag`、`untag` 或 `set_props`，部分为
  `properties`，改前、改后版本引用是对象版本号，摘要记加减了几个标签、改了几个值。

## 查询

CLI、面板与以后的界面共用一份查询描述（`SemanticQuery`：项目、标签、条件、排序、分组、上限），由
`features/query` 编译成只读 SQL。范围是一个项目里未删除的非文件夹节点。

- 标签条件要求同时带有。字段条件只匹配当前标签带这个字段的对象：没打标签的文档不算“为空”；去掉标签后保留的旧值不参与筛选。
- 文字比较不分大小写并做 NFKC（全角等同半角），经注册的 `semantic_fold` 函数，与名称唯一性同一规则。
- “不等于”包含未设置；勾选的“未勾选”同时包含 `false` 与未设置。
- 多选“包含”命中任一给出的选项，“不包含”要求一个都没有；单选、多选按选项名或 ID 匹配，选项名写错时报错并列出选项。
- 日期按日历日字面比较；日期时间按绝对时刻比较（`unixepoch`），不按字符串。内建 `created`、`updated` 接受 `YYYY-MM-DD`（宿主当地零点）或毫秒时间戳。
- 排序：数字按数值，单选按选项顺序，没有值的排最后；默认按最近修改。分组支持单选、多选（对象出现在每个选项组）、勾选和内建 `type`。
- 分组按数量从多到少；数量相同时单选、多选按选项顺序，空组最后。
- `limit` 为 1–200，另给满足条件的总数与 `truncated`。字段名写错时报 `unknown_property` 并列出可用字段。
- 字段 ID 只接受安全字符后才内联进 JSON 路径，其余全部参数化；编译结果用 `statement.readonly` 复核。
- `matchSemanticQuery` 只取满足条件的文档 ID，不设上限、不排序，给项目概览把字段条件和界面上的其他筛选叠在一起用，含义与上面相同。

列表一次读出一批对象的标签（`listObjectTags`）与版本、字段值（`listObjectValues`，只含当前标签带来的字段），不逐个 `readObject`。

## 恢复

`restoreObject(write, toRevision)` 把标签与值恢复成某个保留版本（0 表示从未写过的空状态），作为一次新写入：
加版本、入账，不改写历史。超出保留范围的版本报 `invalid_value`。

## 改动标签与字段本身

`features/schema-changes` 定义改动种类与摘要，`infrastructure/sqlite/sqliteSemanticSchemaChanges.ts` 实现。每次操作是一个事务，
在 `semantic_schema_changes` 记一行“批次”：摘要（名称取当时的名称、受影响对象数）、撤回差量、执行者（来自入口绑定的执行者，
Agent 由运行记录查出）。受影响的对象各加一个版本、留快照，别处按旧版本的写入会报冲突；批量操作不逐个入账本。

| 操作 | 做什么 | 撤回 |
|---|---|---|
| 改名（标签、字段） | 查重名与相近名（排除自己）；插件字段只读，字段名不能含 `.` | 名称已被占用或之后又改过名时报 `undo_conflict` |
| 合并标签 | 带来源标签的对象改带目标（已带的只去掉来源，保留原打标签时间）；目标补上来源有而它没有的字段；来源软删除；值不动 | 来源恢复，对象重新带上来源，之前没有目标标签的去掉目标，补上的字段去掉 |
| 删除标签 | 从对象上去掉，标签软删除，值保留 | 标签与对象上的标签回来 |
| 删除字段 | 软删除，从所有标签的字段里消失，值不动 | 原样显示 |
| 改类型 | 先预览每个已填的值能转、转不了、会变空；执行时能转的换成新值，其余清除，原值全记进差量 | 类型、选项与这些值恢复；之后又改过类型或选项时报冲突 |
| 改选项 | 带 ID 的保留（可改名、调顺序），不带的新建，没列出的删除；用到被删选项的值清除（多选只去掉那一项） | 选项与这些值恢复 |

改类型统一先把值转成文字再按目标类型解析（单选、多选之间按选项 ID 直接转）：数字去掉千分位，勾选认是/否、true/false 等，
日期认 `-` `/` `.` 和年月日写法，只有日期的转日期时间补当地零点并带那天的时区。改成单选、多选时，原来就是单选、多选的沿用选项，
否则按已有文字出现的先后生成，多选按逗号、顿号、分号拆开，超过 50 种报错。

撤回按差量反向应用，不整份覆盖：之后别处对同一对象的改动保留；已被物理删除的文档跳过。调用方可在同一事务里用
`attachToChange` 附上自己的撤回数据，`undoChange` 原样交还。已撤回的再撤回报 `already_undone`，找不到报 `change_not_found`。

## 存储

值每个对象一行 JSONB（`semantic_object_values.property_values`），键是字段 ID。按本机实测，万级文档任意字段
扫描约 1–5ms，不为字段建索引；集合到十万行时再给常用字段加表达式索引。标签单独成表，按标签反查有索引。

## 目录与验证

- `definitions/`：合同、错误码与入口参数。
- `functions/`：名称归一化、相近名称、值校验。
- `infrastructure/sqlite/`：表结构、schema provider 与读写实现。
- `features/query/`：查询描述、编译器与执行。
- `features/schema-changes/`：改动种类、摘要与预览合同，值的类型转换。

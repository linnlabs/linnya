# Image Processing Domain

`image-processing` 给 Agent 处理素材图片：量裁边、墨迹转透明、磨砂、透视、坐标网格、程序纹理，以及把生图模型出的纯色底宫格切成透明小图。入口是 Core CLI 的 `linnya image`（用法见 [Core CLI](../../app-hosts/linnya/application/core-cli/README.md#素材处理)），各文档类型共用。

只做文档类型自己做不到、必须改像素的处理。裁剪取景、调色、形状遮罩、投影这类文档能原生表达的（例如 Slides 的 `crop`、`adjust`、`maskShape`、`shadow`），交给文档本身：原图留在文稿里，导出后仍可修改。

## 职责

- `orchestration/imageProcessing.ts` 与 `sliceSheet.ts`：每种操作一个入口，输入编码后的图片 bytes 和参数，返回 `ImageProcessingOutcome`。可预期的失败（读不出、参数不成立、底色不适用）以 `status: 'failed'` 加错误码返回，不抛异常。
- `functions/`：不依赖 sharp 的纯计算。`perspectiveWarp.ts` 是单应矩阵与双线性取样，`inkAlpha.ts` 由纸色和墨色换算透明度，`gridOverlay.ts` 生成网格的 SVG；`sheetBackground.ts`、`sheetMatte.ts`、`sheetPieces.ts` 分别是宫格的底色实测、去底和分块。
- `shared/pixelCodec.ts`：各操作共用的解码、编码与失败结果。
- `definitions/imageProcessing.ts`：参数、结果、错误码与尺寸上限。

## 不变量

- 本 domain 不读路径、不写文件，文件边界归调用方。CLI 只读当前对话工作目录，结果写进它的 `assets/`。
- 只接受 JPEG、PNG、WebP，按文件头判断；超过 1 亿像素的输入不解码。
- 解码时先按 EXIF 摆正，再缩到长边 2400（网格 1600）。位置、区域和裁剪都按宽高的 0–1 比例给出，量的是摆正后的图，与原图尺寸无关。
- 有透明的结果出 PNG，整张不透明的出 JPEG（质量 90）。墨迹、透视、颗粒和切出的小图总是出 PNG。
- 不新增依赖，全部用宿主已有的 sharp。在 30 张博物馆、产品与拓片照片上实测，单次处理的进程峰值 118–244MB（含 Node 与加载代码约 105MB），结束即释放。

## 各操作的约定

- **trim**：与左上角颜色相差在容差内的四周都算边（白边、扫描黑边、纯色水印条）。没有边时四边都是 0。
- **ink**：只用于白纸或浅底。纸色取 2px 边框的亮度中位数，低于 170 报 `background_not_light`。比纸色暗 8% 以内算纸（全透明），最暗的 1% 算满墨。用纸色而不用全图分位数，是因为拓片大半是墨，按分位数拉伸会把字口的纸算成半透明。已经是透明底的图保留原透明度，只换颜色。
- **frost**：只模糊区域、可选圆角，卡片的底色、描边和投影由文档原生形状叠在上面。给了宽高比时先居中裁成该比例，与文档里铺满页面、不写焦点时显示的部分一致。
- **perspective**：四个角按左上、右上、右下、左下顺时针给出，必须围成凸四边形且面积至少占画布 1%。四边形外透明，取样按预乘透明度处理，边缘不发黑。
- **grid**：列号从 0 起，行号从 A 起，最多 26 等分。标签用通用无衬线字体。
- **texture**：`paper` 是不透明纸纹，`grain` 是透明颗粒层（亮点白、暗点黑，离中灰越远越不透明），强弱交给文档的透明度。

## 宫格切图（slice）

生图模型一次画多个小元素（图标、贴纸、装饰）时，让它画在纯色底上，再由 `sliceSheet` 切成一张张透明 PNG。模型被要求“透明背景”时常画出假的灰白棋盘格，那不是透明。

- **底色实测**：取 3px 边框逐通道的中位数，不假设标准的 `#FF00FF` 或 `#00FF00`。各通道的中位绝对偏差超过 8 判为不是纯色底，报 `background_not_uniform`，不硬切。假棋盘格实测偏差 16，真纯色底在 2 左右。
- **去底**：品红、绿底按键色通道的超出量算透明度（绿看 G 比 max(R,B) 高多少，品红看 min(R,B) 比 G 高多少，再用底色自身的超出量归一），由观测色反解出前景色，再把残留的键色分量压下去。其余纯色底（白、灰）从边框泛洪，元素内部和底色相近的白色与边框不连通，保得住。在 18 张生图色键素材上，透明度误差中位约 1.2/255。
- **键色怎么选**：默认品红，主体本身是粉、紫、洋红时用绿。主体和底色同一色系时会被当成底抠掉（例如绿底上的绿叶），检查图上一眼可见。
- **分块**：默认在缩到长边 600 的透明度图上找连通块，相距两像素以内的笔画并成一块。外接框长边不到全图长边 2% 的当碎屑丢掉；按外接框而不按像素数，细长的剑、钥匙才不会被误丢。长边不到中位块三分之一、且离某个大块不到它长边 15% 的碎片（溅出的水珠、烟雾）并进那个大块。元素挨得太近粘成一块时按 `grid` 等分，每格收紧到不透明的范围，空格子不出。
- **检查图**：所有块排在灰色棋盘格上并标序号，与输出顺序（从上到下、从左到右）一致。小块按最近邻放大到占满一格，残边看得出来。
- 最多 64 块，超过时报 `too_many_pieces`。透明玻璃这类半透明主体在色键下会碎成几块，这时改按格子切。

## 性能

`perspective`、`ink`、`grain` 和 `slice` 的逐像素循环在 App Server 主线程上执行。同一组图上透视最慢约 0.5 秒（输出 2400px），2400px 的宫格切图约 0.25 秒，其余操作都在 0.3 秒内。期间其他对话的流式输出会停顿这么久；以后有更重的逐像素处理（例如边缘抠图）时，再把它们移到工作线程。

## 错误码

| 错误码 | 含义 |
| --- | --- |
| `image_unreadable` | 不是 JPEG、PNG、WebP，解码失败，或超过像素上限 |
| `invalid_options` | 参数不成立：区域越界、四边形自交或太小、尺寸或等分数超限，或 `slice` 指定的键色与实测底色不符 |
| `background_not_light` | `ink` 的底色不是白纸或浅底 |
| `background_not_uniform` | `slice` 的边框颜色不一致，不是纯色底（例如画出来的棋盘格） |
| `no_pieces` | `slice` 在图上没找到元素 |
| `too_many_pieces` | `slice` 找到的块超过 64，多半是元素粘连或底上有杂点，改按格子切 |

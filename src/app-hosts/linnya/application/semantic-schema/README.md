# 标签管理

界面（项目概览文件页“标签”筛选菜单底部的“管理标签…”）和 `linnya schema` 管理命令共用的入口：读出标签与字段、
看用在哪里、预览影响、执行改动、整批撤回。改动本身由[语义层](../../../../domains/semantic-layer/README.md)完成；
本模块负责把[保存的筛选](../project-overview/README.md)在同一事务里一起改写，并把文档、项目和对话名称补齐给界面。

## 合同

`@app/schemas` 的 `semantic-schema-management`，通道 `semantic-schema:manage`，动作：

- `read`：标签（不在回收站的文档数、名称相近的其他标签、带的字段、谁新建的）、字段（类型、选项、挂在哪些标签上、填了值的文档数）与最近 50 批改动。
- `usage`：带这个标签或填了这个字段的文档（按项目分组，最多 200 份）与引用它的保存的筛选。
- `preview`：执行前的影响，不写库。改选项的影响通过试做一次再回滚得到。
- `apply`：执行一批改动，返回这批改动与新的概览。语义层错误（重名、相近名、插件字段只读等）作为失败结果返回，带候选。
- `undo`：整批撤回。
- `set_tag_fields`：整体替换标签带的字段；值不迁移、不删除，不记改动批次。

标签、字段可写 ID 或名称：界面传 ID，命令行传名称。

## 保存的筛选

条件里存的是 ID，改名不受影响。其余改动在语义层改动的同一事务里改写整个工作区的保存的筛选，改写前后的定义附在这批改动上：

- 合并：标签条件换成目标标签。
- 删除标签：去掉这个标签条件。
- 删除字段：去掉这个字段的条件；看板按它分列的改回表格。
- 改类型：去掉这个字段的条件（旧值未必还成立）；新类型不是单选时，看板按它分列的改回表格。
- 删除选项：去掉用到被删选项的条件。

撤回时只恢复之后没再被改过的筛选（当前定义仍是改写后的样子），其余跳过并返回个数。
界面在每次写入后重读文档与保存的筛选；正在看的保存的筛选若被改写，按新定义重新套用，界面上临时条件里已不存在的标签或字段去掉。

# Research 应用用例（工程预览）

目标是充分调查、准确解释、深入浅出的长文章。Default Agent 与 deep-research Skill 1.4 保持原有行为；新版研究入口尚未切换前端，也未宣称稳定的质量优势。

## 当前工程合同

Host 通过唯一的 research_run 入口按固定顺序组织调查、调查复核、初稿、两份并行独立评审、一次修订。四类角色继承用户模型，每个 child 显式 800 步；不使用通用委派、TaskState、旧 Leader 或自动增殖角色。网页深搜仍可选。

角色与阶段提示见 [Agent Registry](../../agent-registry/README.md)。每阶段自包含问题、读者、材料范围、上一版文档和适用方法资源。Skill 是共同方法真源，不复制四份 Skill；反馈规则是版本化的小型增量，不改变 Default 的正式 Skill。

## 文档与接纳

当前只开放显式 Host 工程入口：调用方在已有 `host_tool_call` 中声明问题、读者、open/fixed/update 模式及 Workspace 材料，原始用户请求也完整进入各阶段。普通 `send --agent research_v1` 尚不能推断范围，会在接纳前明确拒绝；附件、旧会话、编辑器引用等未绑定上下文也会拒绝，不能静默丢失后改为开放网页研究。普通产品入口的范围确认与这些材料的正式交接仍待实现，不将此工程入口宣称为已完成的前端研究功能。

阶段以单份 Markdown final answer 返回，Host 通过 [正式文档适配器](../../adapters/research-documents/README.md) create-only 保存、回读全文并绑定 canonical 引用。研究记录、原始评审、初稿和修订稿分开保存，不把研究记录混入文章。角色不持有正式 Workspace 写入工具。

阶段回执只绑定实际父 run、工具调用、冻结请求、输入 inode/正文与引用 hash、child identity 和输出。文档创建与输出回执同事务；run 状态、取消、恢复和成本仍由 RunSupervisor/EventStore/Audit 负责，不建立第二个运行状态机。

后继开始前和产出后都比较输入与正式 current 投影。用户编辑或移除输入时保留已有候选与旧绑定，返回 inputs_changed，停止后继；必须重新接纳研究任务，不能静默复用旧评审、覆盖用户稿或改名假装恢复。同一调用恢复重用冻结身份与产物，不重新发送已完成 child。

## 边界与限制

- delivered 仅表示六个阶段产物已保存并核对其输入版本，不表示观点正确、全部证据已核实或文章通过质量验收。
- registered child 从冻结 descriptor 取得自身工具名单，执行入口在 decorator、缓存和 owner 前拒绝未授权工具；嵌套网页深搜使用自己的名单。明确拒绝是可结算的工具失败，不冒充恢复能力缺失。
- fixed 模式禁止 Web/Knowledge 取得工具，角色请求还限制外部事实和无关文件。Shell 用于计算；它在完全访问下不是网络或文件系统沙箱，不能把这些约束称为操作系统隔离。
- 双评审只收到相同初稿和原始调查，不收到对方评审。当前权限不是独立项目级沙箱；真实读取行为仍需审计。
- 第一次修订后暂不自动复核或继续修改。窄复核与一次定点修正必须另经已知失效回归验证，不能演变成修到通过。
- 本实现不恢复旧研究 Agent，也不增加 Judge 工具、证据数据库、图谱、通用工作流引擎或强制贝叶斯评分。

工程验收需覆盖真实 SQLite/Markdown/Citation、工具生命周期、并行评审、中断恢复、取消、输入变更和历史重载。工程通过后才做已知失效回归与未调试选题对照，分别报告相对改善、全文质量和流程成本。

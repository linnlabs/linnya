# Research 产品职责与交接边界

目标是充分调查、准确解释、深入浅出的长文章。前端入口仍为“研究”，身份仍为
`research_v1`。主 Agent 使用正常 Conversation、TaskState、通用 `subagent`
与 Workspace 文件工具；Host 不自动推进研究阶段，不另建 Workflow。Default
Agent 与研究父子角色共用正式 deep-research Skill；版本和资源由
[Skills owner](../../../../features/skills/README.md) 维护。工程闭环不等于已经证明跨题稳定的质量优势。

## 正式名称、版本与维护范围

| 名称 | 含义与维护位置 |
| --- | --- |
| Deep Research / 前端“研究” | 正式的研究文章能力；项目会话和 CLI 使用同一入口 |
| `research_v1` | 已持久化的 Agent 身份与 promptKey；`v1` 不是试验开关，也不是 Skill 版本 |
| `research_*_v1` | 当前四种专项调查、复核角色身份，由父角色通过普通 subagent 调用 |
| `deep-research` | 研究方法 Skill 的 slug；方法、写作与图文资源由 Skills owner 维护，独立版本化 |
| `deep_research_*` | 旧 beta / CLI 实验身份；停止接纳新根运行，仅留历史解析与兼容恢复所需定义 |

产品展示名与持久身份分开。改显示名称不需要迁移旧 run；如确需改 Agent ID，须同时设计会话选择、请求、descriptor 和恢复迁移，不能把旧 key 静默别名到新流程。历史实现参见[退役研究角色](../../agent-registry/agents/deep_research/README.md)。

正式维护的真源是本页、Agent Registry、Skills 和通用工具 owner 文档。已结束的实验不继续作为生产操作指南；正式 benchmark 和业务回归保留，原始研究资料不进入公开源码或构建依赖。源码中的正式入口、实际运行进程加载的版本、Desktop 安装包发布是三个不同事实；发布仍按[构建与验收](../../../../../docs/development/build-and-test.md)执行。

当前研究交付目标是可追溯、深入浅出的研究文章，仍需核查关键事实与推论。完整 `research_v1` 也可以由消费方插件注册为受管协调子类型；该注册必须声明直接研究叶子范围、隔离父历史与环境，并由消费方负责业务输入及产物版本接纳。平台不自动把完整研究类型加入所有 Agent 的目录。

通用持久 child 首次执行目标 request admission，再冻结范围、真实系统提示、原始 delegation 和自身委派权限。研究 owner 对 delegation.prompt 接纳严格 JSON `{request_id, scope}`，scope 沿用 ResearchRunArgs；显式 fixed/update 材料仍走原边界，不从自然语言或父 scope 猜测。根研究请求不使用此 envelope，原入口保持不变。

消费方的条件版本与结果适用性由消费方拥有。通用子任务成功、两评审齐备、文章保存、业务接纳与事实正确分别判断；本接入不恢复旧研究阶段认证工具，也不提供固定材料的硬沙箱。

## 职责与材料交接

父 Agent 持续负责调查、解释、调查记录、文章初稿和一次修订。专项调查与成文前调查复核按实际缺口选用；父提示要求最终交付前取得同一初稿的论证复核、来源与数字复核。四种专项角色继承父模型，默认不继承父会话历史，最多 800
Graph 步，不再委派其他 Agent。它们作为普通已注册子类型供父 Agent 选择，没有研究专属的 caller 白名单，也不增加前端菜单。

通用 `subagent`
只有 description、prompt 和可选 subagent_type。研究父 Agent 在 prompt 中明确原问题、读者、用户约束、唯一
`Review target`
稿件路径、核查材料路径、可补查范围、具体缺口和独立输出路径。调查请求标明尚未验证的前提，先核对是否成立再追问原因，允许子 Agent 否定前提，不预定其结论。不能把近完整文章复制给子 Agent 重写，也不能假定子 Agent 自动知道父会话或 TaskState。调用沿现有 runner 串行执行，真实轨迹进入标准子任务卡和详情。

评审按指定路径读取和检索，不搜索项目根来发现同伴意见，不读取另一份成稿评审；获准的成文前调查复核可以作为共同背景。意外取得同伴意见须报告暴露，不能据此宣称评审独立。这些是系统提示和任务请求中的职责要求，**不是同项目文件权限或运行时隔离保证**。实验必须核查实际工具调用及返回，串读样本保留并标为受污染。

评审提供问题和核查证据，不代写替换句；父作者自行核实、重推并修订。具体输出边界见 [Agent Registry 的研究角色合同](../../agent-registry/README.md#主研究-agent-与专项子职责-v1)。原句有错不自动证明新的说法成立，这也不禁止有明确依据和前提的条件推断。

## 文档保存与最终交付

父角色在完整文章的构思、写作或仅修订任务之前，明确通过 Skill 读取
`references/article-craft.md`，再按入口读取写作目录与适用文体卡；当前会话已读则不重复加载。调查后根据材料与证据选择写法，而非预先套统一提纲。正文须面向指定读者交代问题为何重要、必要背景、现状及运行机制，在推论前解释必要概念，并让段落沿问题与证据衔接。允许结论先行、事件开篇和不同文体，不固定章节，不越过材料边界补造背景。已有语义回读同时检查读者能否仅凭正文理解，不以模型自身常识替文章补缺。此为父提示与Skill职责，非资源自动注入或强制执行关卡；质量效果仍需完整文章验证。

父子角色用普通 `write_file`、`edit_file` 保存 Markdown，按工具结果使用
`read_file` 核对真实保存稿。Markdown 编译、Citation、pending
revision、写入冲突等沿用各自 owner 的通用合同。子任务产物由现有成功写入事件提取为 Workspace
inode，不引入研究回调。

调查记录、初稿、每份原始评审和修订稿使用不同路径。父 Agent 读取初稿及两份原始意见，回到来源和计算接受、缩小或拒绝重要意见，亲自完成一次修订并回读。在已有回读中对比初稿与修订稿的重要新增、改写和删除，保留仍会实质改变解释的反证与条件；不另增检查阶段或删除理由登记。最终回答链接已保存文章与原始评审，说明关键未解决问题。保存成功、子任务完成与内容正确是不同事实。不通过追加评审循环追求“通过”，不把研究日志混入面向读者的正文。

语义回读必须查看实际保存的相关段落及受影响结论；文件统计、hash、引用列表或首尾片段不能证明已重读这些文字。该要求由父提示指导，不新增读取工具字段或机械正确性状态。

父系统提示明确区分证据引用 `[@XXXXXX]` 与普通文件链接：引用使用本轮工具连同来源上下文返回的 canonical ref，不自行生成。初稿与终稿中的重要外部事实、数字和直接引文就近保留正式引用，计算说明引用其来源输入；书目、来源名称或文件链接不能替代。父 Agent 在已有最终回读中检查引用是否随修订保留；依赖外部证据的保存稿若缺少正式引用，应补齐可取得的引用或明确说明缺口。该要求属于研究文章交付，不要求所有 Markdown 都有引用，也不增加通用工具的引用数量门槛。

保存旧稿、不在两评审之间改初稿、检查修订传播和核对版本仍是父子任务责任。当前不再提供研究阶段 create-only 提交、输入版本锁定、原子产物接纳或双评审齐备认证。普通文件工具的能力不等于这些已撤回的研究保证。材料变化后需要重新判断受影响的评审；预算或证据不足时如实交代，不能把 TaskState 勾选或 child 成功当作全文交付。

## 接纳与恢复

项目会话选择“研究”或 CLI
`send --agent research_v1`，普通请求以开放调查接纳。原请求、正式历史与编辑器上下文各走既有通道；无项目或本轮图片附件在接纳前拒绝。

CLI `--research-scope-json`
声明 question、reader、open/fixed/update、Workspace 材料和时间范围；接纳后随请求冻结为 researchScope。显式范围拒绝未绑定的历史、附件和编辑器上下文；fixed/update 要有正式材料。fixed 禁止外部查找的要求进入父系统提示，父再明确交给每个子任务；不再通过 Web/Knowledge
decorator 或文件工具实施研究特判。Shell 权限沿通用设置执行，真实任务越界仍需审计。

新研究和普通子任务复用持久 child
admission、RunSupervisor、EventStore、Audit 与通用工具恢复。TaskState 只记录计划，不是运行真源。旧
`research_run`、 `submit_research_document` 和 `complete_research`
已退出后端执行注册；不保留特殊旧配置来绕过恢复兼容性检查。依赖旧研究配置的暂停任务明确拒绝续跑，应保留文档并从新会话开始。历史事件、工具展示合同和已保存文档保留；既有旧回执表不删除，也不再新建或写入。曾带 input_documents 的历史 subagent 卡通过只读展示 schema 解析；新的调用不接受该参数。旧普通 pending 调用若仍携带该参数，会按新严格参数校验失败，不会偷偷启用旧交接协议。

## 方法与验证

研究方法与写作资料继续从唯一正式内置 Skill 及资源加载。父/子角色 system
prompt 确定职责，具体委派 prompt 给出本题问题与材料；没有自动阶段 system
reminder。角色与方法维护位置见
[Agent Registry](../../agent-registry/README.md)。不新增 Judge、图谱、评分或专用评审工具。

工程验收覆盖普通文件读写、父写稿与子评审、模型继承、实际子任务输入、取消恢复、产物提取及实时/历史投影。质量实验另外分别报告相对改善、全文质量、完成率和成本；本次通用合同回撤不作为任何方法有效性的证据。

# 项目删除

Desktop 的项目删除是跨 Project、Conversation、Commands 和文件存储的 App 用例。
入口为 Project IPC → `ProjectDeletionUseCasePort`；不能直接调用项目记录的物理删除。

1. 校验项目存在且允许删除，默认项目拒绝。
2. 将项目内会话 ID 写入持久删除清单，再逐条调用同一个 Conversation cleanup 用例。
3. 每条会话先停止运行并等待输出收口，清理工作目录、专属 artifact、审批、卡片和历史事实。
4. 全部完成后，在一个同步事务中确认项目没有新增会话，再删除项目记录；文档、待办及项目绑定由正式外键级联处理。

文件系统操作不能回滚。失败时保留项目及原删除清单，明确报告可能已有部分内容删除；用户重试继续
持久 cleanup job。清单没有会话外键，因为会话事实删除后，metadata 或 job 收尾仍可能失败。
启动先恢复 Conversation cleanup job，项目入口保留供用户再次确认完成。删除期间新建的会话会阻止
最终项目提交，下次重试补入清单，不能通过 `SET NULL` 将其移到无项目历史。

清理只针对项目内会话。其他项目、原本无项目的会话、共享知识库和其他 owner 的资产引用保持不变。
附件引用随对应事实/文档删除；全局 asset 字节继续由既有无引用 GC 在启动时回收，不能在线调用
全库 GC，也不能删除仍被其他文档或会话引用的文件。历史版本已经解除项目归属的会话不自动追溯删除。

本用例不改变 CLI `deleteEmpty` 的只删空项目合同。相邻集成测试使用真实 SQLite、文件系统和正式
Conversation cleanup 装配，覆盖关联清理、范围隔离、部分失败、事实删除后的失败恢复及新增会话阻止提交。

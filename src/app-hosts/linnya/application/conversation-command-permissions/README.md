# 对话命令权限

全局档位和内部数据配置归 Commands 设置 authority。此 Host 用例拥有当前工作区的对话档位、生命周期和批量收紧。没有显式选择的对话在新根 run 接纳时跟随全局。显式选择只覆盖档位，根快照继续携带独立的内部数据开关和固定的 GUI、IPC、进程策略。子 run 和恢复使用原快照。

- **读取与写入**。App Server 从 SQLite 恢复已提交选择。运行时只读取 Host 当前选择。Desktop 修改须通过主窗口 main frame 的专用 IPC，RPC 在 Host 校验对话归属、选择版本和全局版本。变更和逐项历史共享事务，提交成功才更新内存。Host 初始化能力只接受全新的对话，用于需要预先确定档位的产品流程。
- **历史**。当前选择、档位修改和某次根运行实际使用的策略有独立身份。每次修改在同一事务里投影成对话时间线的一行记录（`command_permission_change`，锚在当时最后一个事件之后，与客户端提示同一套重建与截断规则），历史对话打开也能看到。运行摘要随接纳事务保存，供审计回答“这次运行按哪一档执行”，根运行终态可释放恢复描述符。
- **全局调低**。预览绑定全局版本和当前工作区受影响的显式设置。用户可修改全局或同时调低较高的覆盖值。批量选择先在 SQLite 提交并保留待完成记录，随后持久化全局设置。全局写失败时回报已调低的数量，旧全局仍可回读。下次启动或同目标重试时按版本对账，避免覆盖后来保存的全局选择。

底栏和设置页共用 [Commands 档位合同](../../../../../packages/schemas/src/commands/conversationCommandPermission.ts)。命令授权、审批记忆和执行事实仍由 [Commands](../../../../domains/commands/README.md) 管理。

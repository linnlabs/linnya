# Agent 内部存储访问

该 adapter 只负责 Linnya 内部物理存储的路径识别和 Host 文件访问准入。路径由 App 组合根
传入；授权和审批回复复用 Commands 的公开合同，平台 Shell 限制由 command-runtime 执行。
它不读凭据内容、不拥有全局权限设置，也不管理操作系统进程。

受保护位置包括应用数据、Workspace 物理数据、Desktop profile 和外部 CLI 连接凭据。
当前对话工作目录和受管插件 CLI 运行文件是明确例外。必须解析真实路径，不能只比较用户
输入字符串；不存在的目标通过现有祖先解析，支持首次创建文件和原子替换。

Shell 静态路径预检只负责尽早弹出审批。动态拼接路径无法可靠预测，由操作系统拒绝读取；
Agent 如需继续，应在新的调用中明确请求内部存储授权。拒绝后不自动重放可能已有副作用的
整条命令。文件工具在读取正文和导入图片前执行同一权限门。

1/2 档允许本次或保存当前对话规则；文件规则匹配 canonical 文件和会话目录，不能授权同目录
其他文件或 Shell。完全访问直接通过。审批复用 Commands 的持久化和取消流程，保存失败不
降级成一次性允许。模型和 Web 的正式凭据环境变量由生产组合根提供名称，在受限 Shell
launch 时移除，避免文件保护被环境继承绕过；不读取或记录其值。

macOS 接入系统进程树文件边界；Windows 通过独立账户实现并行命令隔离，详见
[Windows owner](../../../../infra/adapters/command-runtime/windows/isolation/README.md)。审批预检不能代替平台限制。
Windows 使用 NTFS 对象权限，Host 必须在受保护目录内创建 staging，再发布内容；不能直接移动
外部文件入库。平台权限和安装包测试须单独记录，不能以编译成功代替实际权限验收。

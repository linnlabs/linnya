# 图表：选图与证据纪律

图表是正文证据的一部分，不是装饰。只有读者需要看清比较、变化、构成或关系，并且数字来自实际取得的材料或已执行的计算时才画图。没有可靠的量化材料就不硬画；只需精确查数或只有三五个数时用表格；纯定性、叙事或作品研究可以完全不用统计图。不设每篇文章的图表数量或类型配额，也不为版面多样去换不适合数据的类型。

图表的语法、字段和写入规则只在内置 Skill `linnya-markdown` 的 `references/chart.md`：先用 `skill` 激活 `linnya-markdown`，再调用 `skill(action="read_resource", skill_name="linnya-markdown", resource_path="references/chart.md")` 读取。这里只回答：画不画、画哪种、怎样不画错。

## 先说读者要比较什么，再选类型

| 读者任务 | 类型 | 需要注意 |
| --- | --- | --- |
| 排名、跨主体比较、正负贡献 | `bar`（类目名长时用横向） | 数值轴含零；堆叠要有意义；百分比堆叠只用于比较构成 |
| 有序观测期的趋势、转折与差距 | `line` | 只画实际观测点；缺测不补零；估计值与观测值分开标明 |
| 同口径序列的规模及其变化 | `area` | 零基线有意义才用；多个系列互相遮挡时改用 `line` |
| 少数互斥部分占同一整体的份额 | `pie` / `doughnut` | 只画一个整体；份数多或差距小时改用横向 `bar` |
| 两个数值变量的关联、群组与异常点 | `scatter` | 不画趋势线，不据一张散点断言因果；需要辨认的点写 `pointLabels` |
| 同一量尺上的多维轮廓 | `radar` | 异质指标先在研究计算中规范化，并在正文说明方法；至少三个维度 |
| 规模与比率、观测值与有依据的目标值一起读 | `combo` | 两个轴分别标明单位；不用缩放轴制造相关性 |

## 把图当作证据来写

- 数据来自实际取得的材料或已执行的计算；不编造、不用 0 代替缺测、不拿口径不兼容的数据硬凑一张图。
- 单位、时间/地域/人群范围、分母、来源版本和关键处理方法写在图旁的正文里；图的标题说明在比较什么，不写结论口号。
- 估计、预测与情景同观测分开，在系列名或标题中标明（例如“2026E（预测）”）。
- 来源引用放在图后紧邻的段落，使用正式引用；多来源的图在该段逐一说明各系列出处。图本身没有来源字段。
- 数据更新后，同步检查图的标题、相邻结论和说明；不能让图改了而结论停在旧数据。
- 先明确比较任务，再选图形态与色系：同组多指标用分组柱；可加总的部分用堆叠；跨组构成用百分比堆叠；长标签与排名优先横向条形。颜色不能替代图形选择。
- 使用预设色系名：单指标或同类序列优先单色系，多类别优先蓝杏粉紫，也可选青蓝绿或雾蓝玫瑰；同一篇报告保持稳定的实体含义，不为“多样”每图随机换色。九套色系和准确字段写法见 `linnya-markdown` 的参考页。
- 沿色带连续取色，不交错冷暖色，不为了颜色好看重排数据。分组/堆叠每组保持同一系列色序；柱图按类目着色只用于单系列。八色仍难辨认或对象更多时优先拆图、聚合或用表格；聚合必须解释口径。
- 自定义色只用于用户要求、跨图固定实体映射或突出重点；不要随意拼红绿组合，也不要把明度和饱和度同时压低。细线用线型、标签补充辨认；默认视图、暗色与导出都要检查可读性。
- 图提供证据，正文给出判断：默认视图应足以支撑正文结论，不要求读者悬停、筛选才看懂核心。

## 保存后回读

写入后用 `read_file` 回读：图表以系统规范化后的文本出现，键序和缩进不由你决定。核对类型、类目与系列顺序、数值和单位是否同研究记录及正文一致。写入若被拒绝，按诊断给出的字段路径和原因修正后重写；一次写入不会只成功一部分。

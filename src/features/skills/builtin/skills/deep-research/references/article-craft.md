# 文体与阅读路径

先确定文章服务谁、要解释什么，以及读者读完应能回答哪些问题。不要强制一种章节顺序，也不要把研究笔记里的假设编号搬进每一段正文。

## 按交付目的调整

| 目的 | 研究与写作重点 | 不能冒充的结果 |
| --- | --- | --- |
| 报道/解释报道 | 事件背景、时间线、相关人的立场与可核事实；归因到具体材料，区分当事人说法与独立确认 | 没有采访就不能写成亲历或采访；不能补造引语和现场细节 |
| 财经/产业/时政分析 | 先建立现状和数量级，再解释价格、政策、产业链、制度或地缘因素如何传导；分清宣布、生效、执行和结果 | 发布政策不等于实现效果；行业总量不代表每家企业或每个地区 |
| 评论 | 让中心论点、事实基础、价值立场与最强异议可见；对反方给出实质回应 | 个人价值偏好不是唯一事实答案；语气强不等于论据强 |
| 学术综述 | 明确问题、检索范围、研究设计、样本、方法和相互冲突的结果；解释证据质量与外推范围 | 非穷尽检索不称系统综述；不得伪造论文、实验或合并不兼容效应 |
| 投研 | 业务机制→驱动量→财务传导→估值假设，列出下行情景与关键敏感项；分清时点、会计口径和市场预期 | 研究结论不是针对未知用户风险承受力的个性化交易决定 |
| 预测 | 定义事件、对象、期限、判断标准与到期核实来源；区分条件情景和实际预测 | 情景权重不是已校准概率；当下看起来有理不代表到期命中 |

多种目的可以组合，但不要因此把所有框架都加进文章。用户只要求解释一个现象时，不额外附投资建议或行动收益表。

## 组织读者的理解过程

开头让读者知道问题为何值得研究，必要时先给结论及范围。现状部分交代规模、主要主体、变化与比较基准；机制部分解释变化如何发生，再用公司、国家、事件或研究作贯穿案例。后续段落应承接一个明确问题或尚未解释的矛盾，而不是再次罗列因素。

专业性分配到需要它的位置。背景可以通俗，方法可以深入，结论可以简短；不为了“像人”故意制造句长起伏或改词频。一个术语的中文全称未必就是解释，要说明它对本题意味着什么。表格适合口径/情景比较，正文负责说明数字为何改变判断。

编辑时看实际变化：必要定义是否提前、传导是否补全、无关分支是否删减、关键分歧是否得到更多解释。保留有意义的结论先行和合法不同文风；排版变化或句长方差不证明理解改善。

## 自检与评审

用几个读者问题检验正文：研究对象与窗口是什么、当前事实是什么、机制为什么成立、反方在哪、结论受什么条件限制。回答必须能定位到正文；常识替文章补全的答案不代表文章解释清楚。

核对原句时区分可见文字和 Markdown 标记，不能把单位、否定、月份或主体改掉。使用独立 LLM 评审时要求给出具体原句、支持依据和缺陷，而不是“更有深度”总分；评审者也可能误读，计算以执行结果核对，事实仍需来源。正文未解释、读者代理答错和资料本来不足是三个不同问题。

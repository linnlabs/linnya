# 项目概览

项目概览分文件、对话两页，每个项目记住本次运行里上次看的页。

文件页是项目级文件表：跨文件夹展示可见文档，支持名称和正文搜索、类型/时间/位置/标签筛选、排序及本机列偏好。

工具条上方一排是保存的筛选：“全部文件”、固定的筛选（超过 5 个收进“更多”，正在看的那个换到最后一个位置）和
“Agent 建议”。条件、排序或布局与所选那项不同时，全部文件上出现“保存筛选”，保存的筛选上出现“已改动 · 另存为新的 ·
保存修改”。保存前若已有条件相同的筛选，先提示打开它，坚持时仍然保存。右键一项可重命名、删除；删除只丢条件，
界面回到全部文件并保留当前条件。字段条件（多来自 Agent 建的筛选）显示在工具条上，只能清除，由 Backend 求值。“标签”筛选菜单底部的“管理标签…”打开[标签管理](../semantic-schema/README.md)；标签或字段改动后整份重读文档与保存的筛选。

布局有表格和看板。看板按一个可写的单选字段分列，列序同选项顺序，没填的一列放最后；标签不带这个字段的文档不在看板里，
下方说明有几份。卡片用指针拖动（不用系统拖放）：拖起一张微斜的纸跟手，松手落在另一列就写这个字段，先在界面上挪过去，
写入后补读这份文档；失败（含版本冲突）时说明原因并按当前值复原。
资源库内部文档不在表中。数据口径由 Host 的 `application/project-overview` 定义。

对话页列出项目里的对话：标题（置顶的标题后带图钉）、Agent、轮次、改过的文档数、最近活动（本窗口观察到正在回复时显示“正在回复”）和占用；
右侧详情给第一个问题、最后的答复、改过的文档（可打开，已删除的标出）和占用分项。搜索覆盖标题和可读对话内容，
命中片段已在详情里完整出现时不重复显示。数据口径由 Host 的 `application/project-conversations` 定义。
列表随时读取（页签上要显示数量）；占用只在对话页打开时分批补测，全部测完才在页头显示总占用。
置顶、改名、删除（二次确认）和打开对话由页面装配层接到对话领域，与侧栏同一套；清理过程文件（二次确认）走存储空间接口。
窄窗口时详情栏收起。设置里的存储空间不再列出每个对话。

- `definitions/`：行模型、筛选与列布局合同（文件页），对话页的筛选、排序和对话写操作端口。列布局版本为 1，所有项目共用本机偏好。
- `functions/`：数据转换、筛选、排序、展示文案、列布局变换和刷新范围判断。
- `orchestration/`：读取快照、合并工作区变更、正文搜索；对话列表、分批测量占用、对话搜索与详情、清理过程文件。同项目读取串行执行，期间的新事件留给下一轮；切换项目后旧响应失效。正文搜索随查询或文档快照变化重新执行，失败时明确提示仅按名称显示结果。
- `store/`：知识库弹窗状态和持久化列布局；不存项目文档的第二份持久化副本。
- `ui/`：文件页虚拟表、保存的筛选那一排、保存/重命名弹层、看板、筛选与列设置；对话页（表、详情与“更多”菜单）。名称列固定，其他列可隐藏、拖动排序、调宽；列设置也支持 Alt+↑/↓ 排序。

页面由 `app/pages/ProjectOverviewPage` 装配。文档类型、图标及插件名来自注册表；打开文件前必须将节点类型转换为注册表中的 `activeDocumentType`，不能把数据库类型直接传给导航。插件不可用时沿用现有说明。跨领域的文件/对话导航与知识库关联由 app 层处理。

正文搜索复用 VFS 行索引，最多返回 500 处命中，达到上限时提示；搜索失败不展示上一次查询的结果。根目录筛选只含根目录文件，其他文件夹筛选包含其子文件夹。

验收入口：相关 Vitest 测试，以及 `scripts/e2e/conversation-navigation/run-electron-conversation-navigation-e2e.mjs` 的 `project-overview` 场景（通过 `LINNYA_CONVERSATION_E2E_SCENARIO` 选择）。真实 Desktop 场景使用隔离临时数据库，验证导航、筛选、列设置、知识库关联、变更刷新及大量文档的虚拟渲染。

当前边界：插件用户编辑未完整进入账本时只展示修改时间；CLI 经运行入口写入的来源目前显示为 Linnya AI。这两项来源精度由各写入入口后续补齐，不由本视图推测。

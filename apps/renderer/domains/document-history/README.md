# 文档历史面板

Core 负责通用交互，不理解插件版本载荷。入口在 Header More；操作和插件菜单合并为一个菜单。
版本展示规则、身份与后端合同见 [Core 文档历史](../../../../src/domains/document-history/README.md)。

- `definitions`：面板状态与 IPC port；`store` 仅同步持有状态。
- `orchestration`：加载、选择、恢复及冲突后刷新。关闭使旧请求失效，迟到响应不能重新打开面板。
- `infrastructure`：调用经过 schema 校验的 document-history:list/restore。
- `ui`：复用 Modal、ActionButtons、AlertDialog，滚动由 Modal 管理。通过 Modal 的 height 固定窗口高度
  （760px，上限为视口高度的 88%），不随加载、空状态或预览内容伸缩；标题和底部操作固定，超出内容在正文内滚动。
  正文填满可用高度，插件预览容器通过 flex 传递剩余空间，插件负责内部对齐。
- `locales`：中文/英文注册；显示版本真实提交时间。
  恢复产生的版本另显示“恢复自 {来源时间}”，刷新和后续成为历史时仍保留标注，不把主时间改成来源时间。

插件通过 document type contribution 提供 historyPreviewComponent，接收 documentId/versionId。
Header More 仅在当前文档类型已启用且贡献历史预览时显示入口。目前仅 Slides 开放；Editor 与 Mindmap 不显示文档级历史入口，也不删除其后台版本存储。Editor 原有块级历史是独立功能，不受此入口控制。
切换版本会卸载旧组件；关闭、切换文档、插件停用均卸载面板。插件组件自行释放预览资源，不能更新当前编辑状态。
恢复当前版本禁用；恢复其他版本先确认，携带已看到的 current identity。冲突时只刷新，不自动重试覆盖。

## 浏览与恢复边界

面板展示打开或手动刷新时的列表快照，不用定时器移动时间锚点，也不因浏览而锁住数据库版本。
没有新的成功提交时，停留半小时或两天不会触发清理。其他会话继续保存时，列表可能过期；用户可刷新列表，
恢复遇到 current 冲突或目标已清理时提示并刷新，必须重新选择、确认。预览不是可恢复性的永久保证。
恢复成功明确提示并刷新到新版本；恢复前的成功版本仍在最近五条中，可再次选中恢复，但以后也遵守保留规则。
确认文案须明确：恢复不截断所选版本之后的历史，最近五个成功版本包含新恢复版本；其余版本可能在本次恢复或后续保存时按时间间隔选留、清理，不能承诺所有较新版本永久保留。
失败草稿不是成功历史，恢复会清除它，确认文案必须说明。确认期间禁止修改目标；关闭窗口不能撤销已经发出的恢复。

# 编辑器块状态/策略管理（Block Policy）PRD

> 备注：这是一个**独立功能 PRD**，与 Citation 并行规划。写完后我们会回到 citation 继续推进。
>
> 代码背景（已确认存在的接入点）：
> - 块菜单：`features/blockActionMenu/*`（通过 provider 注册菜单项）
> - 块移动：`extensions/core/commands/MoveCommands.js`（拖拽移动 rootBlock）
> - 块删除：`extensions/core/commands/RemoveCommands.js`（删除 rootBlock）
>
> 本 PRD 只定义需求与交互，不写实现细节代码。

## 1. 背景与问题

编辑器已经具备较完善的块体系（`doc -> rootBlock -> contentBlock{1}`）与交互能力（拖拽、块菜单、AI 写作、批注、历史等）。但目前缺少一个“块级别的通用状态/策略层”，导致以下问题难以优雅解决：

- 用户容易误操作：误删、误拖动、误转换块类型。
- 某些“系统联动块”（例如未来的参考文献容器块 Bibliography）需要强约束（必须在文末、不可删除、不可随意移动），否则会导致结构不一致与导出混乱。
- 我们希望支持更多文档排版行为：置顶/置底（Pin Top/Bottom）、锁定等，而不是在每个功能里做特判。

## 2. 目标（Goals）

### 2.1 核心目标
- **提供统一的块策略模型**：用一套可扩展的 schema 描述每个 `rootBlock` 的行为约束。
- **软锁/半锁/硬锁**：
  - **软锁/半锁（Soft Lock）**：防误删、防误移动、防误转换，但允许编辑内容（这是重要需求）。
  - **硬锁（Hard Lock）**：除非解锁，否则禁止任何修改（包括内容编辑、删除、移动、转换、AI 写入、自动写入）。
- **置顶/置底（Pin）**：支持将块标记为必须保持在顶部或底部，并在拖拽/移动等入口统一遵守。
- **持久化与兼容**：块策略随文档 JSON 一起保存；旧文档无该字段时默认行为不变。

### 2.2 对 Citation 的直接价值（动机）
- Bibliography（参考文献容器块）未来天然需要：**Pin Bottom +（至少）不可删除**。
- 通过“通用块策略”实现，比 citation 内部特判更可维护、低耦合。

## 3. 非目标（Non-Goals）

- 不在本 PRD 内定义“参考文献条目格式化/渲染”细节（属于 citation PRD）。
- 不在本 PRD 内引入复杂的全局排序规则（例如多组 pinned 区域、跨章节排序等）。
- 不在本 PRD 内实现权限/协作（多人编辑）层面的复杂冲突解决。

## 4. 术语与定义

- **RootBlock**：文档中一段内容的容器块（`rootBlock` 节点）。
- **ContentBlock**：rootBlock 内部唯一的内容节点（baseBlock/headingBlock/...）。
- **Block Policy（块策略）**：附加在 rootBlock 上的一组约束，决定用户/系统对该块可执行哪些操作。

## 5. 需求规格

## 5.1 块策略类型（核心）

每个 `rootBlock` 具备一个策略字段（概念上），推荐包含以下维度：

### 5.1.1 Lock 模式（锁定）

定义三态（或二态 + 扩展字段也可，但 PRD 按三态描述）：

- **Unlocked（未锁定）**
  - 允许：编辑内容 / 删除块 / 移动块 / 转换块类型 / AI 写入 / 自动写入。

- **Soft Lock（软锁/半锁）**
  - **允许**：编辑内容（用户手动输入、粘贴、格式化等）。
  - **禁止**：
    - 删除整个块（rootBlock）
    - 移动块（拖拽/置顶置底命令）
    - 转换块类型（base->heading 等）
    - 由系统触发的“结构性改写”（例如 AI 一键重写整个块、某些自动规范化写入）
  - **备注**：软锁的核心是“防误操作”，不是防编辑内容。

- **Hard Lock（硬锁）**
  - **禁止任何修改**，包括但不限于：
    - 编辑内容（输入、删除字符、粘贴、格式化）
    - 删除块
    - 移动块
    - 转换块类型
    - AI 写入 / 自动写入
  - UX 上必须提供清晰的“已锁定”提示与解锁入口（如果用户有权限）。

### 5.1.2 Pin 模式（置顶/置底）

三态：
- **None**：不固定位置
- **Pin Top**：必须位于文档顶部区域（最前一段或 pinned-top 区域）
- **Pin Bottom**：必须位于文档底部区域（文末）

约束要求：
- 用户拖拽移动时必须遵守 pin 规则（例如 pinned-bottom 不允许拖到中间）。
- 当用户尝试违反约束时：
  - 交互层面给明确提示（光标/占位条/Toast）
  - 命令层面必须兜底拒绝（避免漏网）

### 5.1.3 System-managed（系统管理块，可选扩展）

用于表达“该块由系统维护结构/位置”，例如 Bibliography：
- 建议策略组合：`pinBottom = true` + `hardLock = true`（或 `softLock` + content 只读，取决于最终 Bibliography 的编辑策略）
- 该字段不是必须，但能帮助功能模块避免写死“bibliography 特判”。

## 5.2 用户可见的 UI/UX

### 5.2.1 块菜单入口（BlockActionMenu）

在块菜单中新增分组（示例命名）：
- **块状态**
  - 锁定：未锁定 / 软锁 / 硬锁（根据当前状态显示切换项）
  - 置顶 / 取消置顶
  - 置底 / 取消置底

菜单项规则：
- 当块为硬锁时：大多数会破坏内容的菜单项应显示 disabled，并附说明。
- 当块为软锁时：删除/移动/转换类项 disabled；内容编辑类（如文字颜色）可用。

### 5.2.2 视觉提示（BlockView 左侧控制岛）

建议在 `BlockLeftHandleGroup`（左侧控制岛）区域显示轻量图标：
- 🔒（软锁/硬锁区分：空心/实心或 tooltip 文本区分）
- 📌（置顶/置底通过 tooltip 或上下箭头区分）

交互：
- Hover 显示 tooltip：说明当前约束（例如“软锁：不可删除/移动，可编辑内容”）。
- 点击图标可快速打开块菜单到“块状态”分组（可选）。

### 5.2.3 操作被拒绝时的反馈

必须提供统一反馈策略（避免“没反应”）：
- 删除被拒绝：Toast 或轻量提示 “该块已软锁，禁止删除”
- 拖拽被拒绝：拖拽占位条不出现或出现禁止样式 + 提示
- 编辑被拒绝（硬锁）：输入无效时提示一次（避免每个 keypress 都弹提示，需节流）

## 5.3 行为约束（必须覆盖的入口）

### 5.3.1 删除
- 删除 rootBlock 的所有入口必须遵守锁定策略：
  - 键盘删除块（Backspace 等）
  - 块菜单删除
  - 代码命令删除（`RemoveCommands.js`）

软锁：禁止删除块；硬锁：禁止。

### 5.3.2 移动/拖拽
- 拖拽/移动命令必须遵守：
  - 软锁：禁止移动
  - 硬锁：禁止移动
  - Pin Top/Bottom：禁止移动到不允许区域（对未锁定块也生效）

### 5.3.3 内容编辑
- 软锁：允许编辑内容（核心需求）
- 硬锁：禁止编辑内容（包括粘贴、格式化）

### 5.3.4 块类型转换（convert）
- 软锁：禁止
- 硬锁：禁止

## 6. 数据与持久化

### 6.1 存储位置（推荐）
- 策略存储在 `rootBlock.attrs` 中，随 ProseMirror JSON 持久化。
- 兼容性：
  - 旧文档没有该字段 → 视为 Unlocked + no pin（默认行为不变）
  - 新字段必须可选/有默认值

### 6.2 Schema 演进
- 后续可逐步扩展更多 flag，例如：
  - `allowAiWrite`（允许 AI 写入但禁止删除/移动）
  - `allowAutoNormalize`（允许系统插件做结构规范化）
  - `protectedReason`（用于 UI 文案提示）

## 7. 与 Citation 的联动（明确约束）

当引入 BibliographyBlock 后（citation PRD）：
- Bibliography 所在 rootBlock 应被标记为：
  - `pin: bottom`
  - `lock: hard`（或至少 soft + 内容只读，取决于 bibliograhy 是否允许用户编辑）
- Citation 模块不应在内部再写“强制文末/不可删除”的特判，而应复用 Block Policy。

## 8. 测试与验收（高层）

### 8.1 单元测试（逻辑）
- 策略判定函数：给定 policy + action，输出 allow/deny + reason。
- Pin 规则：移动到非法区域应被拒绝。

### 8.2 集成测试（编辑器命令级）
- 调用删除命令（对应 RemoveCommands）在 soft/hard lock 下行为正确。
- 调用移动命令（对应 MoveCommands）在 soft/hard lock 与 pin 下行为正确。
- 硬锁下输入/粘贴等内容修改被拦截（至少能证明“transaction 不落盘”）。

## 9. 开放问题（需要后续讨论，但不阻塞 PRD）

1) **软锁是否允许“局部格式化”**：例如颜色/加粗算不算编辑内容？（建议允许，符合“可修改内容”的核心诉求）
2) **硬锁提示节流策略**：避免用户按键时每次都弹 toast（建议同一块/同一秒只提示一次）。
3) **系统块识别方式**：是否需要明确的 `systemManaged` 字段，还是通过组合策略推断即可。

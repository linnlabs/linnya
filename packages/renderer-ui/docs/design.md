# Renderer UI 设计规范

本文补充 [Renderer UI README](../README.md)，定义 Linnya 界面的视觉语言：颜色层级、字阶、间距、圆角、边框、动效、交互状态和图标应该怎样取值、为什么这样取值。它面向 Host、官方插件和新增组件的作者。

事实来源分三层：token 的名称与数值以 [`src/styles/tokens/`](../src/styles/tokens/) 为准；组件 API 与行为以 README 和[使用指南](./usage-guide.md)为准；CSS 归属、选择器命名与样式装载等工程规则以 [Renderer 样式指南](../../../apps/renderer/app/styles/guide/style-guide.md)为准。本文只解释如何在这些 token 之间做选择，不复制完整清单。

## 1. 设计原则

1. **内容优先，界面退后。** 对话正文、文档和用户数据是主角；控件、边框和装饰只在需要时出现。能用留白、字重和表面层级表达分组时，不加线框。
2. **层级来自表面与文字，而不是线条。** 一条视线从页面向内最多穿过一层闭合边框。已经有边框的容器（输入框、卡片、对话框、菜单）内部，按钮和分区不再各自描边，改用透明底的 hover 背景或单边分隔线。
3. **每个值都来自刻度。** 字号、间距、圆角、层级、时长和缓动只从本文的刻度取值。刻度不够用时先讨论是否该新增 token，而不是在业务 CSS 里写一个“刚好合适”的数。
4. **动效说明因果，不做装饰。** 动效只用来解释“这个东西从哪里来、到哪里去、状态变成了什么”。它必须短、可中断，并在用户要求减少动态效果时立即完成。
5. **三套主题语义一致。** `light`、`dark`、`moon-blue` 只改变数值，不改变语义：同一个 token 在三套主题里表达同一层级，文字对比度在每套主题里都满足 WCAG AA。
6. **品牌克制。** 品牌绿只用于主操作、选中、焦点和可交互强调。它不表达警示、错误或“特别重要”，也不用作大面积背景。

## 2. 颜色

### 2.1 表面层级

| token | 用途 |
| --- | --- |
| `--color-bg-default` | 页面与内容画布，例如对话流、文档编辑区 |
| `--color-bg-sidebar` | 侧栏与导航区 |
| `--color-bg-surface` | 独立面板与卡片 |
| `--color-bg-elevated` | 浮在其他表面之上的菜单、弹出层和对话框 |
| `--color-bg-subtle` | 凹陷区域：代码块、只读值、轻量标签底色 |

浅色主题下 default、surface 与 elevated 都接近白色，层级主要靠边框和投影；暗色主题下表面逐级提亮（页面最暗）。因此**同一层内容只能使用一种表面 token**：如果一个区域在浅色下“看起来和页面一样”，就应该使用 default，而不是碰巧同为白色的 surface，否则暗色下会出现一块不同底色的接缝。

由多个子组件拼成的复合区域（例如对话宿主的消息画布、输入区背板和渐隐带）应由根组件暴露一个背景变量，子组件统一引用它；所在页面只覆盖这个变量，不分别覆盖子组件背景。

### 2.2 文字层级

| token | 用途 | 最低对比度 |
| --- | --- | --- |
| `--color-text-primary` | 正文、标题、主要标签 | 7:1 |
| `--color-text-secondary` | 次要正文、说明、未选中的导航项 | 7:1 |
| `--color-text-tertiary` | 元信息、时间、辅助说明 | 4.5:1 |
| `--color-text-muted` | 弱化的标签与图标 | 4.5:1（页面背景） |
| `--color-text-placeholder` | 输入占位与可忽略的提示 | 3:1 |

对比度按 `--color-bg-default` 计算；放在 surface 或 elevated 上时仍须满足 AA。层级按上表递减，暗色主题的 primary 不使用纯白，以减少深底上的光晕。不要用降低 `opacity` 的方式制造次要文字，透明度会随背景变化而失去可控的对比度。

### 2.3 边框

- `--color-border-light`：容器的默认描边和分隔线；`--color-border-default`：需要被看清的控件边界；`--color-border-hover` / `--color-border-focus`：交互中的控件边界。
- 暗色主题的边框是叠加在表面上的透明白色，在任何一级表面上都保持同样的可见度；新增暗色视觉不要用某个固定灰色当边框。
- 需要细线时使用 `--border-width-hairline`：高分屏上是物理 1px（0.5 CSS px），普通屏为 1px。
- 区域内部分组用单边分隔线（`border-top` / `border-bottom`），不再嵌套闭合方框。

### 2.4 强调色

`--color-accent*` 是品牌绿的语义映射，用于主按钮、选中项、激活中的开关与 Tab、焦点环和可交互链接性强调。`moon-blue` 主题把强调色映射为蓝色，因此组件只能引用 `--color-accent*`，不能直接写品牌色阶。

强调色有三种用法，不能混用：作文字、图标、描边时用 `--color-accent`（暗色下偏亮，保证在深底上可读）；作承载反色文字的实底（主按钮等）时用 `--color-accent-solid` 与 `--color-accent-solid-hover`（暗色下更深一档，保证白字 4.5:1）；文字落在强调色浅底（选中、激活的工具条按钮与标签）上时用 `--color-accent-text`，它与 `--color-accent-bg` 的对比度在三套主题里都不低于 4.5:1，`--color-accent` 在暗色浅底上只有约 3.3:1。落在 hover 底（`--color-bg-hover`）这类带色的中性底上时也用 `--color-accent-text`：`--color-accent` 在上面浅色只有 4.49:1、暗色只有 3.9:1。

`--color-accent-light` 是比 `--color-accent` 更亮的**图形**强调色，只用于渐变、光效、静止的强调描边和固定深色蒙层上的图标，不作文字色（白底 3.08:1，月蓝 3.46:1），也不表达状态或充当小圆点与手柄（这些用 `--color-accent`）。`--color-accent-strong-light` 用于强调色的浅填充与选区；强调描边与选区外框用 `--color-border-accent-light`。三者是已发布的公开 token，保留名称，不再新增文字或状态用途。

### 2.5 功能色

每种状态有三类 token，用途不能互换：

| 类别 | token | 用途 |
| --- | --- | --- |
| 基础色 | `--color-success` / `-error` / `-warning` / `-info` | 图标、描边、进度条、状态点 |
| 文字色 | `--color-*-text` | 状态文字；在对应 `*-bg` 与页面背景上满足 AA |
| 背景色 | `--color-*-bg` | 提示条、徽标和状态胶囊的底色 |

基础色不保证作为文字可读（例如警示黄），状态文字必须使用 `*-text`。状态语义固定为：错误和失败用 error；需要用户处理但未失败（不可用、已过期、配额将尽）用 warning；完成用 success；中性提示用 info。状态不能只靠颜色表达，必须同时有文字或图标。

错误文字色 `--color-error-text`（浅色与月蓝 `red-415`，`#d42020`）在白底 5.2:1、`--color-error-bg` 上 4.8:1，是满足 AA 的最亮一档红；不要为了更鲜艳再调浅，也不要换回 `red-450`（`#b91c1c`，6.5:1，偏暗偏褐）。同一错误态里的文字、描边、危险按钮实底保持 `--color-error-text`、`--color-error`、`--color-error` 这一组，不要另写一个红。

文字所在的底必须是 `--color-*-bg` 实色，不要用基础色的半透明做文字底：半透明底的对比度随下面的内容变化，`red-415` 文字在 18% 红底上只有 3.9:1，info 文字在 18% 蓝底上也只有 4.25:1。透明控件悬停、行内错误底这类轻量背景用 `--color-error-bg-subtle`：浅色与月蓝取 `--color-error-bg`，暗色保持 8% 半透明，避免大块深红。`NotificationBar` 的四种类型在浅色与月蓝用 `--color-*-bg`，暗色的 `*-bg` 是大块饱和色，仍用基础色 18% 半透明轻底。

状态色只表达状态：别的功能不要借用。例如块历史里“手动编辑”不是“成功”，用中性文字色；“AI 改写”用强调色。

info 同时是“信息流入”类入口的识别色：导入、上传、同步等把外部内容带进 Linnya 的页面级入口可以使用 info tone，与“新建”类的强调色区分；它不表达状态。

### 2.6 使用规则

| 场景 | 使用 | 不要使用 |
| --- | --- | --- |
| 页面、面板、卡片、浮层底色 | 2.1 的表面 token | 基础色阶、`white`、`#fff` |
| 文字 | 2.2 的文字 token；状态文字用 `--color-*-text` | 功能基础色、`opacity` 降级 |
| 边框与分隔线 | `--color-border-*` | 用文字色或品牌色阶充当中性边框 |
| 主操作实底（反色文字） | `--color-accent-solid`、`--color-accent-solid-hover` 配 `--color-text-on-accent` | 把 `--color-accent` 当白字底色 |
| 克制的高对比按钮（发送、确认编辑） | `--color-bg-inverse`、`--color-bg-inverse-hover` 配 `--color-text-inverse`；浅色为深底白字，暗色为浅底深字 | 固定深灰底配白字（暗色下禁用态会比可用态更亮） |
| 滚动条 | `--scrollbar-thumb-color`、`--scrollbar-thumb-hover-color`、`--scrollbar-track-color` | 固定灰阶 |
| 选中、焦点、强调文字与描边 | `--color-accent`、`--color-accent-bg*`、`--color-focus-ring` | 直接引用 `--color-brand-*` |
| 品牌色浅底（推荐、已选择） | `--color-accent-bg`、`--color-accent-bg-subtle` | 自行用 `color-mix` 调一个新的绿 |
| 状态提示条、徽标 | `--color-*-bg` 配 `--color-*-text`，描边或图标用基础色 | 浅色底配基础色文字 |
| 用户选择的内容颜色、语法高亮 | 所属 domain 的内容色 token | 把内容色上移为通用 token |
| 任何其他颜色 | 上表的语义 token，或 `color-mix()` 叠加语义 token | 十六进制、`rgb()`、`hsl()` 字面量（棘轮 `COLOR-02` 拦截；纯黑纯白遮罩除外） |

基础色阶（`--color-gray-*`、`--color-red-*` 等）只在 token 层使用：它们不随主题切换，业务 CSS 直接引用会在暗色下出现亮底或看不清的文字。调试面板、刻意固定的深色代码面板、品牌标识色，以及外观设置里描述主题本身的预览插画（调色板集中在 `settings/styles/tokens/theme-preview.css`）是仅有的例外，并应在样式旁注明原因。遮罩、投影和固定深色蒙层上的文字可以使用 `--color-black` / `--color-white`，因为它们在所有主题下语义相同。

### 2.7 对比度

| 对象 | 最低对比度（WCAG 2.2） |
| --- | --- |
| 正文与界面文字（< 18px 或 < 14px 加粗） | 4.5:1 |
| 大号文字（≥ 18px，或 ≥ 14px 且 semibold） | 3:1 |
| 理解操作所必需的图标、控件边界与输入框描边 | 3:1 |
| 焦点环与相邻颜色 | 3:1 |
| 占位文字 | 3:1 |
| 禁用控件、纯装饰元素 | 不要求，但禁用态必须同时有 `disabled` 语义 |

对比度按元素实际所在的表面计算，并在三套主题中分别满足。新增颜色组合前先算对比度；已知不达标的组合记录在本文“当前限制”中，不能当作可复用先例。

### 2.8 主题与系统外观

- 每套主题在根元素上同时声明 `color-scheme`（`light`、`moon-blue` 为 light，`dark` 为 dark），原生滚动条、表单控件与下拉弹层随之切换明暗，不需要业务单独适配。
- 需要在当前主题里展示另一套主题（例如外观设置里的选择）时，用简洁抽象的固定插画（白天、月白、夜晚）表达，调色板集中定义、不随当前主题变化；不要用基础色阶临摹，也不要把整页缩略图塞进选项里。
- “跟随系统”是 Host 的外观偏好，不是第四套主题：它只在 `light` 与 `dark` 之间解析，`moon-blue` 必须由用户显式选择。组件只读取解析后的主题 token，不感知偏好本身。

### 2.9 色彩角色

界面里的颜色只属于下面几类，判断一个颜色该用什么，先问它属于哪一类：

| 角色 | 使用 | 说明 |
| --- | --- | --- |
| 中性 | `--color-bg-*`、`--color-text-*`、`--color-border-*` | 界面骨架，不带情绪；没有特殊含义的颜色都落在这里 |
| 强调 | `--color-accent*` | 主操作、选中、焦点与可交互强调；不表达状态。用法见 2.4 |
| 状态 | `--color-error` / `warning` / `success` / `info` 及 `-text`、`-bg`、`-bg-subtle` | 含义固定：失败 / 需处理 / 完成 / 中性提示；必须配图标或文字；其他功能不借用 |
| 内容色 | 编辑器块背景与文字色板、表格列引用色、终端 ANSI、代码高亮 | 用户选择或内容自带，独立于界面主题；不借用状态色，也不被借用为状态色。由所属 domain 在色板文件里集中定义，文件头注明原因 |
| 装饰 | `--color-accent-light` | 渐变、光效、静止强调描边，不承载信息 |
| 主题预览与调试 | 写死色 | 仅限外观设置的主题预览插画和开发期诊断页面 |

## 3. 字体

### 3.1 角色字阶

业务 UI 按内容角色选择字号，字号与行高成对使用：

| 角色 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `caption` | 11 / 16 | 徽标、计数、时间戳、快捷键提示 |
| `footnote` | 12 / 18 | 辅助说明、表单提示、紧凑控件、表头 |
| `body` | 13 / 20 | 默认界面文字：菜单、列表行、按钮、侧栏、表单控件 |
| `prose` | 14 / 22 | 需要连续阅读的文字：对话回答、用户消息、输入框、设置说明 |
| `subtitle` | 15 / 22 | 卡片标题、空态副标题、对话框分组标题 |
| `title` | 18 / 26 | 对话框标题、页面分区标题 |
| `headline` | 22 / 30 | 页面标题 |
| `display` | 28 / 36 | 空态和首屏的主视觉文字 |

对应 token 为 `--font-size-<role>` 与 `--line-height-<role>`。`--font-size-xs` … `--font-size-3xl` 是基础刻度，只在 token 层和文档内容排版（例如编辑器标题层级）中使用。单行控件需要文字与图标垂直居中时可以使用 `line-height: 1`。界面文字最小为 `caption`（11px），不使用 9px、10px；图标字形（×、+ 等）的 `font-size` 属于图标尺寸，不受角色字阶约束。

### 3.2 字重

只有三档：`--font-weight-regular`（400）用于正文，`--font-weight-medium`（500）用于按钮、标签和需要强调的界面文字，`--font-weight-semibold`（600）用于标题。CJK 字形在 700 下过重，强调不使用 bold。

### 3.3 数字与长文本

会变化的数字（计数、用量、计时、表格数值）使用 `font-variant-numeric: tabular-nums`，避免数值变化时整行抖动。可能出现超长无空格字符串（路径、ID、URL）的位置使用 `overflow-wrap: anywhere`，单行标题使用省略号截断并提供完整文本的提示。

### 3.3.1 字体抗锯齿

Host 默认开启 `-webkit-font-smoothing: antialiased`（只在 macOS 有可见差别，笔画更纤细），用户可在“设置 → 外观 → 文字渲染”关闭，关闭后回到系统默认渲染（文字略粗）。样式由 Host 的 `reset.css` 按根元素的 `data-linnya-font-smoothing` 属性决定：只有 `off` 才关闭，属性缺失时开启，启动首帧不会闪。业务组件与插件样式不要自己设置 `font-smoothing`，需要调整文字的轻重时用字重与颜色 token；字重只有 400 / 500 / 600 三档，不要写 450 这类中间值（中文字体多是固定几档，中间值会被映射到不可预期的一档，2026-10-20 实测 450 比 500 还重）。

### 3.4 行距

- 界面文字使用角色自带的固定行高（像素值），让列表行、按钮和输入框的高度可预测；不要给单个组件另写 1.4、1.45 之类的比例。
- 连续阅读的段落使用 `prose` 的 22px（约 1.57 倍），段落之间留 `--space-2`～`--space-3`，而不是继续拉大行高。
- 标题行高收紧（`title` 约 1.44、`headline` 约 1.36），多行标题不显得松散。
- 文档正文等内容排版（编辑器、Markdown 渲染）由内容 owner 定义自己的行高，可以使用 `--line-height-normal` / `--line-height-relaxed`，但同一类内容只能有一种行高。
- 单行控件需要图标与文字垂直居中时用 `line-height: 1` 加 flex 居中，高度由控件高度 token 决定；不要用 24px、28px 之类的像素行高去凑控件高度（刻度棘轮把 24px 及以上的像素行高视为居中高度，不计入债务，但仍不鼓励新增）。
- 行高跟着字号成对选择：同一规则里写了 `--font-size-<role>`，行高就用同一角色的 `--line-height-<role>`。

## 4. 间距

间距使用 4px 网格，token 编号乘以 4 即像素：

| token | 像素 | 典型用途 |
| --- | --- | --- |
| `--space-0-5` | 2 | 紧凑控件内部的图标与文字 |
| `--space-1` | 4 | 图标与文字、同组按钮之间 |
| `--space-1-5` | 6 | 紧凑控件内边距 |
| `--space-2` | 8 | 控件内边距、列表项之间 |
| `--space-2-5` | 10 | 中等控件内边距 |
| `--space-3` | 12 | 卡片内边距、表单项之间 |
| `--space-4` | 16 | 面板内边距、组与组之间 |
| `--space-5` | 20 | 宽松面板内边距 |
| `--space-6` | 24 | 区块之间、对话框内边距 |
| `--space-8` | 32 | 页面分区之间 |
| `--space-10` | 40 | 页面级留白 |

半步（0.5、1.5、2.5）只用于紧凑控件内部。小于 2px 的光学校正可以写 1px，但不能因此复制一套几何常量。

**带边框控件按外尺寸对齐网格。** 控件的外尺寸 = 内边距 + 边框，所以带 1px 边框的输入框、标签和徽标，内边距写成 `calc(var(--space-2) - 1px)`，让外尺寸落在 4px 网格上，而不是写 7px。存量代码里的 3、5、7、9、11、15px 绝大多数就是这个意思，或是在凑固定高度（工具卡标题行 `padding: 7px` 凑出 32px）。遇到奇数内边距不要直接吸附到相邻 token：2026-10-16 的实测里，这样会让每个工具卡标题行 +2px、设置页每行 +1px、存储页列表累计 +508px。先确认它在补偿什么，再改成“token + 控件高度 token + flex 居中”。

大于 40px 的长度（空态留白、固定列宽）是版面尺寸，不属于间距刻度。

`--spacing-xxs` … `--spacing-2xl` 是 2.x 已发布插件仍在按名称使用的旧别名，数值指向对应的 `--space-*`。仓内新代码不得使用，存量由刻度棘轮逐步收敛，下一个 major 删除。

## 5. 圆角

| token | 像素 | 用途 |
| --- | --- | --- |
| `--radius-xs` | 2 | 选区、进度条等细小标记 |
| `--radius-sm` | 4 | 标签、内联代码、复选框、紧凑图标按钮 |
| `--radius-md` | 6 | 按钮、输入框、菜单项等标准控件 |
| `--radius-lg` | 8 | 卡片、工具卡、菜单、弹出层与对话框 |
| `--radius-xl` | 12 | 大面板、对话输入框 |
| `--radius-2xl` | 16 | 空态首屏等大尺寸输入容器 |
| `--radius-full` | — | 胶囊、圆形头像和按钮 |

嵌套时内层圆角等于外层圆角减去两者间距（最小取 `--radius-xs`），让内外轮廓同心。纯圆形元素可以直接写 `border-radius: 50%`。

- 胶囊形元素（滚动条滑块、徽标、开关轨道、计数标签）一律用 `--radius-full`，不要写“约等于半高”的数值（10px、5px），否则高度一变轮廓就不再是胶囊。
- 进度条、引用线、拖放指示线这类 2–3px 的细条用 `--radius-xs`。

## 6. 投影与层级

- 投影只表达“浮起”：菜单、弹出层、对话框和拖拽中的元素。不要用投影代替边框，也不要用投影制造 hover 效果。
- 浮层使用 `--shadow-floating-panel`（自带一圈发丝描边），对话框使用 `--shadow-lg`，静止卡片最多使用 `--shadow-xs`。暗色主题只加重浮层用的 `lg` / `xl`；开关、卡片等小元素用的 `xs` / `sm` / `md` 与浅色保持同一强度，组件不需要、也不应该为暗色单独加深。
- 跨 owner 的浮层只能使用 README 中的 `--linnya-ui-layer-*` 层级。组件内部的局部堆叠用 0–9 的小整数；10 及以上的 z-index 必须来自层级 token。
- 菜单与下拉用 `--linnya-ui-layer-popover`，图片预览遮罩用 `--linnya-ui-layer-image-preview`，需要压过一切的提示与弹层（引用弹层、录音提示、修订弹层、拖放指示线）用 `--linnya-ui-layer-tooltip`；不要再写 9999、10000 这样的“足够大”的数字。

## 7. 动效

### 7.1 时长

| token | 时长 | 用途 |
| --- | --- | --- |
| `--duration-micro` | 100ms | hover、按下等颜色与透明度反馈 |
| `--duration-short` | 150ms | 菜单、提示、开关等小型浮层与状态切换 |
| `--duration-medium` | 200ms | 展开收起、弹出层、Tab 指示器移动 |
| `--duration-long` | 300ms | 对话框、抽屉、面板滑入 |
| `--duration-loop` | 1600ms | 循环动画的一个周期（骨架微光、加载指示） |

`--delay-reveal`（200ms）不是动效时长，而是加载占位的出现延迟：短于它的加载不显示任何占位。减少动态效果时它保持不变，四个时长 token 归零，`--duration-loop` 的循环动画由组件直接停用。

元素越大、移动距离越远，时长越长；离开通常比进入短一档。

### 7.2 缓动

| token | 用途 |
| --- | --- |
| `--ease-standard` | 元素在屏内改变状态、位置或尺寸 |
| `--ease-enter` | 元素进入视图：快速出现，减速落定 |
| `--ease-exit` | 元素离开视图：加速收走 |

进度条、旋转加载等匀速运动使用 `linear`；流式文字的淡入也使用 `linear`（可见的渐变长度等于名义时长，先快后慢的曲线会让同样的时长看起来短得多）。不要使用 CSS 默认的 `ease` 或临时写的 `cubic-bezier`。

### 7.3 规则

- 优先只动画 `opacity` 与 `transform`；需要动画高度时使用 grid `0fr → 1fr` 等不触发逐帧布局的方式。
- `transition` 只列出状态变化时真正改变的属性，不写 `transition: all`：`all` 会让布局、字号和主题切换时的颜色一起被动画，切换主题时界面会出现不同步的渐变。
- 动效必须可以被打断：快速重复触发时从当前状态继续，而不是跳回起点。
- 延迟不是时长：防抖延迟（引用标记悬停的 60ms）、跑马灯的起始延迟不套时长 token；与淡出同步的 `visibility` 延迟则写成同一个 `--duration-*`，保证两者一起被“减少动态效果”归零。
- 循环动画（`infinite`：旋转、脉冲、微光、跑马灯）的周期由动画本身决定，不套时长刻度，也不要求使用 `--ease-*`。
- 用户开启“减少动态效果”时，四个时长 token 会被置为接近 0，经由 token 的过渡自动立即完成。直接写在关键帧里的循环动画（如加载指示）必须自行提供 `prefers-reduced-motion` 规则：装饰性的微光、脉冲、光标闪烁在该偏好下停用；表示“正在进行”的旋转指示可以保留。一次性的进入动画使用 `--duration-*` 与 `--ease-enter`，减少动态效果时随 token 立即完成。
- `--transition-fast` / `--transition-normal` / `--transition-slow` 是 2.x 旧别名，分别指向 micro、medium、long；仓内新代码使用 `--duration-*`。

## 8. 交互状态

| 状态 | 表达方式 |
| --- | --- |
| hover | 透明底控件显示 `--color-bg-hover`；文字或图标可提升一级文字色 |
| active（按下） | `--color-bg-active`；需要触感时可加 `scale(0.98)`，时长用 micro |
| selected | `--color-accent-bg` 底色配 `--color-accent` 文字，或 `--color-bg-active-subtle` 中性选中 |
| disabled | 使用原生 `disabled` 语义，配合 `--color-text-placeholder` 或整体 0.5–0.6 透明度；不能只改颜色 |
| focus-visible | `outline: var(--focus-ring-width) solid var(--color-focus-ring)`，`outline-offset: var(--focus-ring-offset)` |

只在 `:focus-visible` 上显示焦点环，鼠标点击不显示。Host 的 document baseline 已为所有键盘可聚焦元素提供这一焦点环（文本输入、可编辑区与脚本聚焦的 `tabindex="-1"` 容器除外），组件不需要重复声明；组件改用其他焦点表达（例如输入框的强调色边框、行内按钮显露）时，必须保证键盘焦点同样可见。不要在基础选择器上写 `outline: none` 关掉焦点环。

平时隐藏、悬停才出现的行内操作，在所在行 `:focus-within` 时也必须显示，否则键盘用户会聚焦到看不见的按钮。

## 9. 组件规范

### 9.1 通用要求

- **状态完整**：组件定义自己真实存在的 default、hover、active、selected、disabled、focus-visible、loading、error 子集，并在三套主题下检查；不存在的状态不要为清单制造。
- **高度对齐**：同一行并排的按钮、输入框、选择器取同一档 `--control-height-sm`（28）/`md`（32）/`lg`（36）。工具条与行内操作用 sm，表单与对话框正文用 md，页面级入口用 lg。
- **圆角随尺寸**：小控件用 `--radius-sm`，标准控件 `--radius-md`，卡片与浮层 `--radius-lg`；胶囊形只用于页面级入口、筛选标签和状态徽标。嵌套圆角遵守第 5 节的同心规则。
- **边框克制**：容器有闭合边框时，内部控件使用透明底或单边分隔线；需要层级时优先用表面层级，其次用发丝边框，最后才用投影。
- **文字**：控件文字用 `body`（13/20）；标签与按钮可用 medium 字重；控件内不使用 `prose` 以上的字号。
- **可访问性**：使用正确的原生元素与 `aria-*`；图标按钮必须有可访问名称；禁用使用原生 `disabled`；键盘可达且焦点可见。

### 9.2 按钮

新按钮一律使用 `BaseButton`，存量自写按钮在修改所在页面时迁移。`variant` 表达操作在当前区域里的层级，而不是“想要什么颜色”：

| variant | 视觉 | 用途 |
| --- | --- | --- |
| `primary` | 强调色实底（`--color-accent-solid`）、反色文字 | 当前区域唯一的主操作：保存、发送、插入、创建确认 |
| `secondary` | 表面底色加描边 | 与主操作并列的次操作：取消、返回 |
| `ghost` | 透明底加描边 | 已有容器内的次要操作：重置、更多选项 |
| `plain` | 无底无描边，次级文字色；`tone` 可选 accent / info / danger | 工具栏、标题行、列表行与浮层里的轻操作；accent 用于面板内的确认，danger 用于行内删除、清理（静止中性、悬停显红） |
| `danger` | 错误色实底 | 删除、清空等不可撤销操作；需要二次确认的放在确认对话框里 |
| `soft` | 品牌色浅底与细描边 | 推荐但不应抢过主操作的动作，例如引导卡片里的“开始” |
| `tint` | 品牌色平涂浅底（`--color-accent-bg`）、深色文字（`--color-accent-text`） | 占满宽度（`block`）或位于大片留白里的主操作：设置表单底部整条的“添加”“开始分析”。同一个主操作用 `primary` 实底，面积一大视觉重量会失衡 |
| `outline` | 表面底色、发丝描边、轻投影，`tone` 决定颜色 | 页面级入口：`accent` 用于新建，`info` 用于导入、上传，`neutral` 用于普通入口与空态，`danger` 用于页面级的破坏性入口 |

组合规则：

1. 一个区域（对话框、表单、卡片、页面头部）最多一个 `primary`、`tint` 或 `danger`。主操作按面积选风格：紧凑的按钮（对话框和表单底部的 `ActionButtons`、工具栏）用 `primary` 实底；整条占满容器宽度的 `block` 按钮用 `tint` 浅底。
   紧凑的行内面板（公式、尺寸、引用浮层）不放实底按钮，确认用 `plain` + `accent`、取消用 `plain`。
2. 主次成对时次操作在左、主操作在右；对话框与表单底部使用 `ActionButtons`，它由两个 `BaseButton` 组成并保证最小宽度 80px。
3. 同一行的按钮使用同一尺寸、同一形状；不要在同一组里混用胶囊与方角。
4. 前置图标通过 `icon` 插槽放入 14px 槽位，只辅助理解；按钮文字或 `aria-label` 必须能独立说明操作。`block` 按钮带图标时图标贴左、文字视觉居中。
5. 文字使用动词或动宾短语（“新建知识库”“插入引用”），不使用“确定 / OK”这类不说明结果的词，危险操作写明对象。
6. 正在提交时禁用按钮并把文字改为进行时（“发送中…”），不要只换成转圈图标。

调用方只能通过 props、插槽和根节点的 `class` / 布局 `style` 定制外围位置与宽度，不能覆盖 `.linnya-ui-button*` 内部选择器改颜色或尺寸；缺少真实需要的层级时扩展 `BaseButton` 的语义 variant。

### 9.3 图标按钮

没有文字、只有一个图标的按钮使用 `IconButton`；编辑器格式工具条使用 `ToolbarButton`。

| size | 外框 / 图标 | 用途 |
| --- | --- | --- |
| `xs` | 20px / 14px（命中区扩到 24px） | 文字行内与卡片标题行的密集操作：刷新、复制、行内删除 |
| `sm` | 24px / 18px | Header、侧栏行、消息操作 |
| `md` | 28px / 18px | 面板与对话框标题行的关闭、导航 |
| `lg` | 32px / 20px | 与 32px 输入框、选择器并排的添加类操作 |

- 静止为 `--color-text-tertiary`，悬停提亮到主文字色并出现 hover 底色；选中或展开（`active`）用强调色浅底，与 `ToolbarButton` 一致；禁用为占位文字色。
- `variant="subtle"` 静止即有浅底，只用于表单里与输入框并排、需要被看见的添加操作；`variant="overlay"` 只用于叠在图片、视频等内容上的按钮（白色图标，悬停半透明白底，颜色不随主题）；其余一律 `ghost`。overlay 的半透明深色底条与模糊由容器提供，不进组件。
- `tone="danger"` 静止保持中性、悬停显示错误色，用于行内删除与移除；不可撤销的删除仍需确认。
- `label` 必填，同时作为可访问名称与原生提示；外层已有 `HoverTooltip` 时传 `:tooltip="false"`，提示需要附加快捷键时可自行提供 `title`。
- 图标尺寸由 `size` 决定，业务不再给图标写宽高；需要锚定浮层时通过组件暴露的 `element`（或 `resolveIconButtonElement`）取得原生按钮。
- **什么时候不用 `IconButton`**：形状或状态本身就是设计的一部分时保留自己的样式，不要为了统一抹掉它。例如批注面板里按语义着色的圆形按钮（AI、编辑、解决、删除各有色调和悬停放大）、紧贴输入框的分段按钮（密码显隐）、缩略图角上带边框的操作小块、窗口控制与分段页签、带多种状态色的转写按钮。编辑器与思维导图的格式工具条用 `ToolbarButton`。
- 按钮所在的行已经处于 hover 或选中底色时，在行的操作容器上把 `--linnya-ui-icon-button-hover-bg` 设为 `var(--linnya-ui-icon-button-hover-bg-raised)`：它在三套主题里都与行底色保持约 6 的 L\* 差，第二层悬停一眼可见。其它已有底色的容器（如代码块）可以设为更高一档的 hover 语义 token。这是唯一允许调用方调整的视觉入口。

### 9.4 卡片与面板

- 卡片：`--color-bg-surface` 底、`--color-border-light` 描边、`--radius-lg`、内边距 `--space-3`～`--space-4`；可点击卡片 hover 时提升描边到 `--color-border-hover`，不使用位移动画。
- 面板与浮层：`--color-bg-elevated` 底、`--shadow-floating-panel`、`--radius-lg`；对话框使用 `Modal`。
- 卡片内的分组用单边分隔线或间距，不再嵌套卡片。

### 9.5 弹窗

- 使用 `Modal`。标题是弹窗的第一层级：`subtitle`（15/22）、semibold、`--color-text-primary`；不要用比正文还浅的灰色做标题。
- 来源或状态标签放在标题旁，通过 `title-extra` 插槽接入，使用状态徽标的字阶与颜色，不能抢占标题层级。
- 关闭按钮固定在标题行右侧，28px 圆角方块，静止为 `--color-text-tertiary`，悬停提亮到主文字色并出现 hover 底色；形状不随状态变化。
- 底部操作区主操作在右、次操作在左，使用 `ActionButtons`；正文过长时由内容区滚动，标题与操作区保持可见。
- 点击遮罩与 Esc 关闭当前最上层弹窗；含未保存输入的表单弹窗应关闭 `closeOnOverlayClick`，避免误触丢失内容。

### 9.6 列表行

- 侧栏与列表行的名称默认占满整行，溢出用省略号；行内操作（打开、更多）只在悬停、键盘聚焦或其菜单打开时出现，名称也只在这时让出操作区宽度，不为隐藏的按钮常驻留白。
- 行内操作按钮比行 hover 再高一层底色，保证二次悬停有反馈；菜单打开期间保持行的悬停外观，直到菜单关闭。
- 次要信息（时间、数量）靠右并使用 `tabular-nums`，悬停时可由行内操作替换。

### 9.7 输入区与消息画布

对话消息向下滚动时从输入框顶部下方“滚入”输入框背后（进入式，遮罩深度 `--conversation-footer-mask-entry-depth`），不在输入框上方加渐隐带，也不改变这条硬边界。回到底部按钮靠右落在内容列边缘。消息画布与输入区背板共用 `--conversation-host-bg`，页面只覆盖这个变量，避免暗色下出现不同底色的接缝。

**对话文字排版。** 回答、用户消息与输入框使用 `prose`（14 / 22）；工具卡、时间线和元信息保持 `body` 与 `footnote`，让正文与界面文字拉开层级。回答里的 Markdown 垂直节奏**全部用 `em`**，随字号一起缩放：段落上下 0.5em，列表项 0.2em，列表块 0.5em，引用与代码块 0.7em，标题上 1.1em 下 0.4em；行内代码 0.9em。标题字号显式规定（`h1` 1.45em、`h2` 1.2em、`h3` 1.07em、`h4`–`h6` 1em 加粗；14px 正文下约 20 / 17 / 15px），不再依赖浏览器默认的 2em / 1.5em / 1.17em / 0.83em / 0.67em（默认值会让 `h5`、`h6` 比正文还小）。一行汉字数建议在 40–50 个：内容列约 738px 时，14px 约 52 个字，15px 约 49 个，16px 以上会明显偏松；2026-10-19 在真实会话里对比过 13 / 14 / 15 / 16px，15px 读起来偏大，选定 14px。思考内容有意保持 `footnote`（12 / 18）加弱化颜色，层级低于回答。

### 9.8 标签与徽标

- 状态徽标：`caption` 字号、`--radius-sm` 或 `--radius-full`、`--color-*-bg` 底配 `--color-*-text` 文字，高度不超过 20px。
- 筛选与输入标签使用 `TagChip`；数量徽标使用 `tabular-nums`。

### 9.9 文本输入与原位编辑

- 文本输入复用 `CustomTextInput` / `CustomTextarea` 的边框、背景、圆角和 hover / focus 状态；业务组件通过公开扩展入口适配布局，不另造输入框外观。
- 原位编辑（例如名称、标题和图注）在内容与容器宽度不变时，进入或退出编辑应保持外框尺寸、文字位置与换行一致。阅读态与编辑态使用相同的字号、行高、可用宽度和内边距，并预留边框空间；焦点通过颜色表达，不通过放大字号、增高或加宽表达。
- 切换原位编辑时，首帧就应呈现目标状态的背景；替换节点不能让已有悬停底色先消失、再从透明淡入。焦点描边可沿用标准过渡。验收须覆盖切换过程，不能只比较切换前后的静态截图。
- 短文本不能因为切换成 textarea 就展开成默认多行表单。确需自然折行的内容按实际行数决定高度，只有内容或可用宽度变化才重新排版；不得仅在聚焦时扩大，也不得用固定单行高度裁掉已有长文本。文档内容的原位编辑沿用所属内容角色的排版。
- 单行语义的原位编辑使用 Enter 提交、Esc 取消；输入法选字期间不提前提交。失焦提交与校验失败行为由业务 owner 明确定义。

## 10. 图标

平台图标从 `/icons` 获取，单色线性风格，颜色继承 `currentColor`。常用尺寸为 12（徽标）、14（按钮图标槽、密集行内操作）、16（与正文同行的控件）、18（Header、侧栏行与图标按钮）和 20（与 32px 控件并排的操作、卡片与空态）；同一行内同类图标保持同一尺寸，辅助展开箭头按下节单独取值。图标用于帮助理解而非唯一表达，图标按钮必须有可访问名称。品牌标识 `LinnyaIcon` 只用于品牌位置，不作为普通操作图标。

### 10.1 展开箭头

- **辅助标记小一档。** 操作图标旁的展开箭头使用 12px（紧凑工具条）或 14px（普通行内选择器），不随主操作图标放大到 18–20px。按钮命中区仍由控件尺寸决定，不缩小可点击范围。参考文本选区工具条的标题菜单与代码块语言选择器。
- **复用平台字形。** 使用 `/icons` 的 `ChevronIcon`，不在业务里重画箭头，也不覆盖图标内部路径来调粗细。箭头继承控件的文字色，不靠加粗或品牌色抢占主操作的层级。
- **方向表达真实展开态。** 向下打开的折叠内容可由右箭头转为下箭头（90°）；原本向下的选择器箭头打开后转为向上（180°）。导航与指向侧方子菜单的箭头保持其方向，不混用折叠反馈。
- **旋转跟随控件状态。** 过渡使用 `transform`、`--duration-medium` 与 `--ease-standard`；关闭时反向过渡，快速重复触发从当前角度继续。复制、标题等主操作图标保持静止，只旋转辅助箭头。展开、Escape、点击外部和选项完成后的关闭都读取同一个真实展开态，不额外维护一份点击状态。
- **面板与箭头各自归属。** 菜单面板继续使用共享 `DropdownTransition` 的 150ms 淡入与位移动效；替换 `CustomSelect` 的 `arrow-icon` 插槽时，通过 `classNames.trigger` 映射的触发器及其 `aria-expanded` 驱动箭头反馈。减少动态效果时，箭头通过时长 token 立即到达最终方向，面板遵循共享组件的同一偏好。

## 11. 状态呈现

- **空态**：说明当前是什么、可以做什么，最多给出一个主操作；不展示不可用的“即将推出”控件。
- **加载**：结构已知的内容（列表、卡片、消息）使用与最终布局一致的骨架；时长不确定的小范围操作使用行内加载指示。避免整块空白后再一次性出现，也不要用居中的“正在加载…”文字或转圈代替结构已知的内容。
  - 列表使用 `SkeletonRows`：sm / md 单行对应 28 / 32px 行，lg 为带 32px 图标的双行；图标、行尾占位按真实行取舍，左右起点与真实行对齐。
  - 其他版式用 `Skeleton` 包住若干 `SkeletonBlock` 组合，形状和间距照抄真实布局；宽度用固定序列，不随机。
  - 占位在 `--delay-reveal` 后淡入，本地的快速加载不会闪一下；`Skeleton` 自带 `role="status"` 与读屏文案，形状对辅助技术隐藏。
  - 骨架底色只比所在表面高一层（`--linnya-ui-skeleton-bg`），微光很轻，减少动态效果时停止。
- **错误**：就近展示，说明原因与可执行的下一步，使用 error 功能色；不要只用 Toast 告知需要用户处理的问题。

## 12. 刻度棘轮

`pnpm run guard:renderer-style-scale` 扫描 `apps/renderer` 与 `packages/renderer-ui/src` 的 CSS（token owner 文件除外），统计绕过 token 的写死值与基础色阶引用：

| 规则 | 统计内容 |
| --- | --- |
| `SCALE-01-font-size` | px 与 rem 字号（em 与百分比是相对字号，不计） |
| `SCALE-02-font-weight` | 数字字重与 `bold` |
| `SCALE-03-line-height` | 0 与 1 以外的数值行高（24px 及以上的像素行高视为控件居中高度，不计） |
| `SCALE-04-radius` | 非零长度圆角（`50%` 不计） |
| `SCALE-05-spacing` | `padding` / `margin` / `gap` 中大于 1px、不超过 40px 的长度 |
| `SCALE-06-z-index` | 绝对值不小于 10 的 z-index |
| `SCALE-07-duration` | 过渡与动画中的非零时长（`infinite` 循环动画不计） |
| `SCALE-08-easing` | `ease` 系列关键字与 `cubic-bezier()`（`infinite` 循环动画不计） |
| `SCALE-09-legacy-alias` | 旧别名 `--spacing-*` 与 `--transition-*` |
| `COLOR-01-base-palette` | 引用 `--color-gray-*`、`--color-red-*`、`--color-blue-*`、`--color-yellow-*`、`--color-brand-*` 与 `--color-dark-*` 基础色阶（自定义属性定义中同样统计） |
| `COLOR-02-raw-color-literal` | 十六进制、`rgb()` / `rgba()`、`hsl()` 等色彩字面量（含自定义属性定义）；纯黑、纯白及其透明度的遮罩与投影、`url(#id)` 不计。内容色板与 token owner 文件在扫描外，外观设置的主题预览插画 `theme-preview.css` 是唯一按文件列出的例外 |
| `MOTION-01-transition-all` | `transition` / `transition-property` 中的 `all` |

**有意的例外。** 开发期诊断与试验页面（`LlmRequestDebugPanel`、虚拟列表试验页、`debug.css`）不扫描。其它不在刻度上的有意取值，在声明后写 `/* scale-exempt: 原因 */`，该声明不计数；目前用于图标字形的 `font-size`（取色样本、空态图标、关闭 ×）、根字号和防抖延迟。原因必须写明白，评审时按原因判断是否成立，不要用它压计数。

每个文件每条规则的数量记录在 `.baseline/renderer-style-scale.txt`，只允许减少：新增写死值会让 `pnpm run lint:style` 失败；减少后运行 `pnpm run guard:renderer-style-scale:update` 收紧基线。自定义属性的定义不在统计范围内，局部变量如果表达刻度值，应从 token 派生。

## 13. 新增或修改 token

1. 先确认现有 token 无法表达，且至少有两个业务 owner 需要同一语义；单处使用的值留在组件局部。
2. 主题相关 token 必须在三套内置主题中同时定义并满足本文的对比度要求；非主题 token 放在 `:root`。
3. 新增 token 属于 minor，删除、重命名或改变语义属于 major，按[版本与装配检查表](./release-checklist.md)处理，并更新本文与 [CHANGELOG](../CHANGELOG.md)。
4. 运行 `pnpm --dir packages/renderer-ui run gate` 与 `pnpm run lint:style`，并在三套主题下人工检查受影响页面。

## 14. 当前限制

- 部分业务 CSS 仍带有不在刻度上的值，由刻度棘轮和代码评审逐步收敛；基础色阶引用只剩第 2.6 节列出的有意例外。2026-10-17 的存量约 200 处，主要是三类：
  - 奇数内边距与间距（约 90 处，见第 4 节）：每处都在补偿边框或凑固定高度，要随组件迁到控件高度 token 时一起改，不批量吸附。
  - z-index（54 处）：局部堆叠的 10、20 等需要先给局部容器 `isolation: isolate` 再收敛到 0–9；1300、1200、1100 等跨 owner 的值需要先画出真实叠放顺序，再给现值命名新层级。
  - 登场动画的自定义缓动与 0.4s 时长（`AiAssistantInput` 的模型配置遮罩）：需要在真实页面里看节奏后再换成 `--ease-enter`。
- 文本对比度可以用应用内逐页扫描复核：遍历可见文本节点，按有效背景计算对比度并汇总低于 4.5:1（大字 3:1）的组合。2026-10-16 在浅色、暗色、moon-blue 三套主题的项目首页、对话、知识库、插件商店、设置各页和文档编辑页上扫描后，除装饰性的面包屑分隔符外没有低于要求的文字。
- 按下态（active）只持续很短时间，outline info tone 按下时文字对比度约 3.8～4:1，未计入第 2.7 节的要求。

## 15. 细节清单

交付 UI 改动前逐项过一遍。每条都来自一次真实的返工或实测。

1. **量，不要猜。** 改间距、行高、字号前后，对同一组页面做元素尺寸对比和截图逐像素对比，把“几乎看不出”换成数字。工具卡标题 +2px、设置行 +1px 都是这样才发现的。
2. **外尺寸对齐网格。** 带边框的控件用 `calc(token - 1px)`；固定高度来自控件高度 token + flex 居中，不靠 padding 与行高相加（第 4 节）。
3. **同一件东西只有一种写法。** 胶囊用 `--radius-full`、细条用 `--radius-xs`、行高跟字号角色走（第 3、5 节）。
4. **体量也是视觉属性。** 整行宽按钮用 `tint` 浅底，紧凑按钮用 `primary` 实底；迁移同类控件时保留面积与色块深浅（第 9.2 节）。
5. **悬停只做底色变化，除非是链接。** 列表行与卡片悬停时不要让里面的文字、图标变品牌色；只有可点的文字链接用颜色变化表示可点。
6. **动效可打断、可关闭。** 淡出与 `visibility` 延迟用同一个时长 token；延迟不是时长；循环动画自行提供 `prefers-reduced-motion` 规则（第 7.3 节）。
7. **层级有名字。** 跨 owner 的 z-index 只用层级 token，不写 9999（第 6 节）。
8. **文字对比度逐页复核。** 三套主题都扫一遍，低于 4.5:1（大字 3:1）的组合要有记录（第 14 节）。
9. **有意的例外要写原因。** 守卫的 `scale-exempt` 标注必须说明为什么这个值在刻度之外（第 12 节）。
10. **图标按钮必须有名字。** `IconButton` 的 `label` 必填；纯图标的原生 `<button>` 至少要有 `aria-label`。

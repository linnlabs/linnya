# Slides limited manual editing

`manualEditing` owns the Renderer side of limited editing for generated `deck.js` presentations. It provides compiler-projected author targets and temporary visual projections, and submits a strict command against the exact revision/source snapshot. The backend remains the only writer. It may use proven-equivalent projections for eligible atomic/Frame translation, Shape/Image visual size, Shape/Frame fill, independent Text width or an independent blank-page insertion; other edits use the full author compiler. Both paths commit the semantic revision without waiting for PPTX assembly and publish the same revision contract.

## Current interaction

- The toolbar edit button is available only for a ready generated document whose visible RenderModel version equals the build-state revision and with a current slide (including an empty page).
- The slide background is not an author target. Manual hover resolves the same projected target path used by pointer-down: movable objects show a move cursor, selectable-only objects show a pointer, and empty slide background keeps the default cursor. A primary-button press on empty slide background or the surrounding stage gutter clears the current selection. The gutter uses the existing interaction handoff, so inline text is submitted without waiting for persistence and pending writes remain intact. Only the blank viewport/content surfaces own this event; property controls, resize handles, scrollbars and other application panes do not become deselection targets.
- Clicking an object resolves one author hierarchy path from the compiler-projected `authoringAncestorRefs`. The first click selects the outermost visible Frame; another click at the same child location enters the next layer. Once a child is selected, one click on a sibling selects that sibling directly; a click into a different nested branch stops at the first target after the common ancestor. The selection outline alone identifies the current target; no hierarchy label or author-key breadcrumb is rendered. Pointer-down locks the current layer as the gesture owner, so dragging over a child moves the selected Frame rather than switching targets mid-gesture. Releasing promotes the delta to a local pending translation before sending one `translate_by` operation in inches. The pending visual is removed only after the committed RenderModel revision and its current-page image/chart resources form the displayed frame, or rolled back on failure.
- Double-clicking a text-only Text (plain or rich) or plain-string Shape enters [`editingInteraction`](../editingInteraction/README.md), the sole owner of input, IME and interaction handoff. The sibling [`textEditing`](../textEditing/README.md) provides the native DOM view. Clicking another object ends input and selects it immediately while a passive preview retains the submitted text. Submission and frame settlement never hold or reclaim input focus. Multiline and mixed-font strings remain editable when the compiler declares a plain author string.
- After selecting an author object, `Backspace` or `Delete` submits one typed `delete_target` intent. Atomic text, shape, image, table, chart, SVG and formula targets remove only themselves; a Frame removes its complete author subtree. The Stage takes keyboard focus when the user selects on the canvas, but never intercepts deletion from input, textarea, select, button or contenteditable controls. An active inline text session retains ownership of both keys.
- Selecting an object exposes the sibling [`elementProperties`](../elementProperties/README.md) feature only when the compiler projects at least one visible property action: plain-text font size/color, Frame/Shape solid color, Shape/Image visual width/height, or deletion of any author target. The compact toolbar follows the current selected bounds and opens color/size controls on demand; the object toolbar hides during dragging, resizing and inline text input without changing the canvas viewport. A non-empty Text range opens the same toolbar in text-selection scope, emitting local style patches rather than object commands. Deletion-only targets receive the same icon button; the button and keyboard use the same `editingInteraction.deleteSelectedTarget` entry. A truly translate-only target has no property toolbar, and the toolbar does not repeat an author key as a floating title.
- Text-only rich author runs enter the same input session and save complete styled content. Formula-containing author runs remain text-read-only because this editor cannot preserve editable formula structure; they may still move.
- Image and Shape author objects may resize when projected as safe; Table, Chart, SVG Graphic and formula author objects currently only move. Their content/data/source editors remain later independent feature slices.
- Rotation uses the shared box-center rule. Resize translation accounts for both the local dragged-edge displacement and the changed half-size, preserving the opposite world-space anchor for every handle. A top-left rotation formula must not be reused here.
- Resizable Shape/Image selections expose all four corners and four edge midpoints. A small round marker sits inside a larger transparent pointer target. Each gesture keeps the opposite corner or edge midpoint fixed; shapes adjust independent dimensions unless Shift is held, and images always preserve their current aspect ratio; a proportional side drag expands the other axis symmetrically. Pressing or releasing Shift mid-drag recomputes from the last pointer position, through the focused handle's key events. `set_visual_size` carries the final dimensions and optional anchor-compensation `translationDelta` in one atomic edit. Rotated targets project pointer displacement onto their local axes, with the same zoom conversion as the stage. The gesture starts from the currently presented geometry, including queued edits. Pointer capture keeps dragging active outside the handle; local Canvas, selection and property previews update together, with no per-move IPC. Release promotes exactly one final operation into the existing queue before removing the transient preview. Inner text synchronously reflows with the preview box using the shared text-layout algorithm and backend-prepared shaping/metrics facts. Default font size, padding, wrapping and autofit use the same rules as the committed model, so installing the revision does not introduce a second text-size change. No platform measurement or compilation runs per pointer move; snapshots live with their RenderModel revision. Nodes without sufficient prepared facts retain the complete prior node until the formal revision; they never approximate new text layout by moving old lines. Escape/pointer cancellation clears only the current gesture; a click or return to the original size submits nothing. Completion returns keyboard focus to the stage, preserving Delete/Backspace. Accessible numeric inputs remain the keyboard resizing path. Frame resizing remains outside the projected capability contract. Numeric property edits retain the current top-left origin.
- A decorated Flex Frame is selected through its background and moves as one author object. The compiler projects every flattened descendant's `authoringAncestorRefs`; the target mapper turns that relation into the exact RenderNode roots shared by optimistic translation, deletion and parent selection geometry. The parent outline is the world-coordinate union of the visible roots, so a child moved beyond the Frame background remains inside the parent selection. Hit testing still uses each real object polygon rather than the union rectangle, so empty space between members does not become clickable. Active and queued child previews feed the same union before compilation finishes. Child text and visual objects keep their own author identity, so clicking them can still select and edit the child independently. Nested rendered Groups contribute only their outer affected root, avoiding a double transform.

## Slide structure edits through the same queue

The navigator's "+" ([deckNavigator](../deckNavigator/README.md)) enqueues `{ op: 'insert_blank_slide', index }` as an ordinary `ManualEditIntent` without visual previews. The thumbnail menu uses the same path for `duplicate_slide` and `delete_slide` with an exact-snapshot index. It therefore shares exact-revision submission, transport retry, receipts, failure/blocked settlement and the refresh-only retry with object edits. Slide-structure intents never coalesce with each other or with object intents. While the grid view replaces `SlideStage`, the grid records `presentedRevision` once the current document's RenderModel revision is installed; that grid is the visible frame, so queued tickets still settle.

There is no editing mode and no separate AI source-selection mode. `SlideStage` always routes a pointer press to manual editing when an author target is under it, and to source selection only for nodes that carry a source span but no author identity; the two selections are mutually exclusive and keep their own feature stores. `store.enabled` now means "this deck can be written by hand right now": `DeckViewer` derives it from `resolveManualEditingAvailability` and keeps it on while the presented frame catches up with our own revision (`version_not_ready`). Selection does not depend on it; when it is off the interaction still selects (so the object can go to AI) but never translates, deletes, resizes or opens text input. Sending to AI maps the selected author targets to source targets with `findSourceElementsForSelection` (own span, or the painted members of a Frame without one).

## Layers

```text
definitions/
  manualEditingTypes + localized message catalog
functions/
  author-capability target/path projection, hit testing, resize geometry, availability, delete command/shortcut rules, command creation, result messages
orchestration/
  captured resize gesture, serial submit/refresh/receipt workflow
store/
  mode, selected target, gesture preview, queued entries and discriminated submission state (synchronous writes only)
ui/
  localization adapter and resize handles
```

The store never calls IPC and never contains geometry or conflict rules. Generic world-coordinate traversal belongs to the sibling `renderNodeSelection` feature; manual editing contributes only its author-capability predicate and target mapping. `SlidesView` supplies snapshot, IPC and refresh ports to `useManualEditQueue` and provides its narrow submission port to the Stage. The queue owns coalescing, dispatch and explicit ticket settlement; stores only receive synchronous state writes. `submitManualEdit` owns exact-command creation and idempotent transport retry, and returns the backend result before any visual refresh. `flush()` waits for every admitted backend write, rejects save/dependency failures, and does not require the final visual frame; export and Host navigation consume it through documentRuntime. Render-model errors unblock the save barrier with an explicit refresh failure instead of leaving it pending forever. The next intent starts only after the prior committed revision is both the current build version and the installed RenderModel version. `SlideStage` records presentation only when `renderVisualResources` has atomically installed the target page frame. Active, queued and in-progress resize previews share one projection collector for painting, hit testing and passive text geometry, so the canvas does not jump back and a moved or resized target remains selectable at its visible position while compilation catches up. Pointer movement and repeated arrow keys are accumulated within their active gesture before enqueue, and translation deltas are quantized to the compiler's 1e-4-inch grid so the backend can project them. `appendManualEditQueueEntry` merges a still-queued tail entry with an incoming edit of the same field on the same target (the same text-style or image fields, fill, width, visual size, translation, including same-shape translation batches) into one write and therefore one undo step; text sessions, deletions, layer steps, insertions, page actions and undo/redo always stay separate. `errorMessage` is reserved for write failures and participates in `flush()`; prompts for actions that wrote nothing (unsupported copy, oversized image, unfinished IME) use the dismissable `notice` and never block saving, switching or undo. An undo/redo commit may return a `focus`; it travels on the presented settlement, and `revealRequest` lets the canvas reselect those author targets after navigation.

## Conflict and failure behavior

- A stale revision/source snapshot refreshes the document and explains that another operation won.
- An unresolved AI draft refreshes into the existing draft failure screen; manual editing never deletes it.
- Source validation or full-build failure keeps the current compiled revision visible, returns failed to the active ticket and blocked to every dependent queued ticket. Temporary non-text previews roll back; editingInteraction retains corresponding text drafts for recovery. The UI explains that subsequent edits were not submitted. Selecting another object does not clear the failure summary.
- While a command or its complete visual frame is pending, the committed frame remains selectable and property, text, and drag gestures append typed intents with immediate previews. Exact-revision submission remains serialized, so the backend never receives a command against a stale base.
- A committed response is an accepted source revision, not proof that the new pixels are visible. The feature keeps `pendingPresentationRevision` until the matching or newer complete visual frame reaches the stage. It also handles the inverse race where that frame arrives before the command response.
- Command refresh and `workspace.document.updated(version)` refresh carry the target revision into one coalesced read. A completed duplicate is skipped, and a late request for a previously open document cannot reactivate or overwrite the current document.
- If the first IPC response is lost, the workflow retries once with the same command ID; the backend receipt returns the already committed revision instead of creating a duplicate.
- A committed write followed by refresh failure stays awaiting_frame, preserves its preview, and exposes a refresh-only retry; it is never reported as a failed write or submitted again.
- Each admission has a clientOperationId; merged entries retain every identity and bind them to the first ID as the backend commandId. A resolved ticket is durable even when response and presentation happen in one event-loop turn. Document generations reject late results, including A→B→A navigation.
- The Host file-session save barrier drains admitted edits before document switch/close; only then does the switch reset feature state. A RenderModel revision update reconciles selection by stable render ID.

## Performance trace

`Slides/Ipc` records the snapshot read duration, batch count, received block count and retained cache size when verbose diagnostics are enabled.
The `refresh_completed` boundary now covers installation of the complete revision snapshot, including navigation and RenderModel.
`refreshToFrameMs` covers subsequent resource preparation and frame presentation; compare timings with older traces using the old deck/preview boundary accordingly.

Each accepted command uses its UUID as the Renderer/Backend correlation ID. When
`localStorage['linnya.slides.debug']` is set to `verbose`, the Renderer emits structured
`Slides/ManualEditTrace` events for queue admission, request start, retry, response, refresh completion and the first
browser animation frame after the complete target revision is installed. The terminal
`frame_presented` event includes queue wait, dispatch-to-response, input-to-response, response-to-refresh, refresh-to-frame and total
input-to-frame timings. Backend `slides_manual_edit.backend_trace` events use the same command ID and
identify the operation and `projected_edit` versus `full_compile`, including scope wait and compiler phases without logging source or edited content.

## Ordered text author-value previews

Text-content intents carry a typed visual preview alongside style operations, retaining their exact queue order through serialization and frame settlement. `projectTextEditingValues` projects full content, whole-run fields and inherited baseline together; `createPresentedTextEditingTarget` combines those values with the existing geometry projection. Property controls and input/draft presentation consume this narrow public function rather than implementing different rich-text precedence. Canvas still draws pending content through `TextDraftPreview`; adding content to the ordered preview does not introduce another text layout engine or persistent document.

## Complete visual projection

[editingPreview](../editingPreview/README.md) owns paint and layout projection. Canvas, selection, hit testing and editor re-entry consume the same complete nodes. The queue only owns ordered intents and revision settlement; manualEditing no longer owns a partial run-style projection or a Shape-only old-line repositioner. A text-size operation updates layout and box together when exact local facts are available. Flow Text widths with a compiled page replay snapshot reflow through editingPreview; unsupported layout dependencies and missing measurements retain the complete prior frame until formal compilation. A weak cache shares the synchronous result without adding a second store or asynchronous callback lifecycle.

The page supplies `preparePresentation` for structure selection. One logical command prepares once across transport retries and confirms/cancels at its final outcome; the queue does not implement selection rules. See [documentRuntime](../documentRuntime/README.md).


## Selection sets, batch commands and editing history

`selectedTargets` is canonical; `selectedTarget` is the last selected item, derived for single-object controls. Selection normalization excludes an author's descendants when its Frame is selected. `translationPreviews` and `visualPreviews` are ordered arrays, so batch actions share the same geometry, hit testing and rollback as single-object edits.

`batch` contains 1–1000 object operations applied in order (the same target may appear more than once, e.g. the left text-width handle sends a move and a width change), becomes one source write and one semantic revision, and fails atomically. Selection, marquee and guide state never enter history. The backend's history status is authoritative; Renderer only holds revision ID and undo/redo depth. `flush()` means saved, while a ticket's `presented` means the complete resource frame is visible. Saving, refreshing and failed states are distinct.

`pendingPageOperation` covers page-index commands and history restoration until frame settlement. Insertion/paste and navigator actions use it to avoid applying stale displayed page indexes. A document switch clears session clipboard/selection; external source or AI revisions reset the backend editing history stack.

Editing command UI is owned by [editingCommands](../editingCommands/README.md), insertion by [elementInsertion](../elementInsertion/README.md), copy by [elementClipboard](../elementClipboard/README.md), and image changes by [imageEditing](../imageEditing/README.md). See [the user interaction contract](../../docs/editing-experience.md).

## Text width handles

Text boxes expose only width handles (`ManualTextWidthHandles`, `resolveManualTextWidth`): the right handle submits `set_text_width`; the left handle submits one batch of `translate_by` plus `set_text_width` so the right edge stays put. Widths and shifts are on the compiler grid. The gesture freezes the initially presented bounds and zoom, then feeds each width into editingPreview: wrapping, the visible box and selection update together without IPC. Release enqueues the same preview before clearing the gesture; subsequent drags start from the visible pending width. Escape cancels only the current gesture, and save failure rolls back the pending width. A dashed guide retains the width label while the property toolbar is hidden. Independent fixed-height Text and auto-height Text with compiler-provided measurement inputs use the shared exact projection; flow Text uses the compiled page replay through editingPreview, updating affected siblings, paint and hit geometry together. It still saves through the full compiler. Pages with unsupported measurement owners or insufficient prepared facts retain their prior complete frame until compilation. Old saved revisions acquire replay facts on their next successful full compile.

Pending insertions retain complete typed object values in the queue. A newly imported image may also retain its local data URI for preview; this field never enters the command, source or backend history. `pendingInsertions` is derived state, and settlement/failure/reset drops these values. The stage filters out objects already present in the displayed formal frame before handing them to editingPreview. Selection and follow-up editing still begin only after the confirmed frame.

## IPC failure policy

The queue only retries a typed IPC failure explicitly marked `retryable`, reusing the same command ID once.
Validation, unknown transport errors and infrastructure failures do not imply a lost successful response and are not retried.
Business conflict/build outcomes remain normal command results and keep their existing queue settlement behavior.

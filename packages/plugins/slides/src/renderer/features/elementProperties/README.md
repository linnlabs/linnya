# Slides element properties

`elementProperties` owns the limited property controls shown for one selected authoring target. It receives an immutable `ManualEditableTarget`, derives available controls only from the compiler-projected capabilities, and emits a typed manual-edit operation. A target with only `translate` produces no toolbar, and the toolbar does not repeat the target's author key as a heading. It does not own selection, persistence, compilation or RenderModel state.

Supported controls:

- plain Text: font size from 1 through 400 points and `#RRGGBB` text color;
- Frame/Shape: replace the existing background/fill with one solid color;
- Shape: set visual width and height independently in inches; Image: changing either dimension preserves the current effective display ratio. Number changes submit on Enter/blur without a separate Apply-size step;
- every target with a projected `delete` capability: an icon-only delete button; atomic objects remove themselves, and a Frame removes every descendant.

The font-size control shows the current number and an inset dropdown arrow inside one compact input box, following the Conversation model selector’s integrated arrow layout. Its idle surface is borderless; hover anywhere within the control or keyboard focus reveals the input boundary. The compact chevron rotates with the existing expanded state and respects reduced-motion preferences. The input reserves space for the arrow through its public `inputClass`; the button uses its public root class, without targeting shared internal selectors. Its accessible name and hover hint retain “Font size” and the 1–400 pt range. It composes shared `CustomNumberInput`, `ToolbarButton` and `CustomSelect`; no new generic control or alternate property submission path is introduced. The input accepts finite decimals as well as integers, including values outside the preset list. Enter/blur commits through the existing number-field owner; empty/out-of-range values restore the current effective value without submitting, and Escape cancels the draft before blur.

The arrow (or Alt+ArrowDown from the input) opens a bounded, scrollable list of common sizes, including the minimum and maximum. Shared list navigation owns Arrow/Home/End and option focus; selecting a value uses the same `commitNumber` path, closes the list and returns focus to its trigger. The current effective value selects an exact matching preset; a custom size does not falsely select a nearby value. The list participates in the existing single-popover state, pane placement and outside-click ownership, so opening text color/size or selecting another object disposes it. List motion, options and keyboard behavior remain with CustomSelect; Slides owns only presets and positioning.

The delete icon uses the same `delete-selected` intent as Backspace/Delete through the Stage and `editingInteraction` owner; property fields do not construct a parallel delete command. A deletion-only target still receives a compact toolbar. Accessible names and hover text distinguish ordinary deletion from Frame subtree deletion without printing “Delete group” beside the icon.

The toolbar intentionally has no create, group, reparent, gradient editor, image crop/source editor, rich-text run editor or free-form property path. `elementPropertyOperations.ts` validates the same user-value ranges as the shared command codec and checks both target kind and projected capability before creating an operation. `SlideStage` connects the toolbar to `editingInteraction`, which passes accepted operations to `manualEditing`, which owns optimistic presentation and submission lifecycle.

Shape text remains editable in place, but the current compiler does not project `set_text_style` for Shape: its toolbar offers fill and size, not font size/text color. Controls must follow projected capabilities rather than infer extra authoring support from the presence of text.

The color palette reuses the stable Renderer UI color-picker contract, shared number/text inputs and action buttons. Preset selection compares canonical HEX values; a solid color outside the palette selects the custom-color row with a swatch and checkmark. Non-solid fill selects neither. Custom color is a single standard-height menu row with a persistent submenu arrow, rather than an expanding card. Hover opens its child form without moving focus; click, Enter/Space or ArrowRight opens and focuses it. Choosing a preset submits directly.

The child form switches between HSV (plane and hue/saturation/brightness sliders) and RGB (three 0–255 sliders plus exact integer inputs) with shared `SegmentedTabs`. Both modes retain the HEX input, live draft swatch and right-aligned shared `ActionButtons`. `useCustomColorDraft` coordinates all three representations of one local draft; mode changes do not convert or submit a color. Invalid HEX or empty/fractional/out-of-range RGB input disables Apply in either mode, preserves the input for correction and keeps the last valid preview. It never silently clamps an invalid number or applies stale HEX. HSV edits retain hue through black/grayscale instead of round-tripping through HEX and losing the selected hue. Only Apply/Enter emits a color; Cancel/Escape emits no operation, and reopening starts from the current target color.

The feature keeps its Slides-specific palette, draft/conversion and localization. It consumes existing public UI components without a new shared color state or a second command path.

HSV and RGB channels use Renderer UI `CustomSlider` in compact density, shared with the deck zoom control. Slides receives numeric updates and owns color normalization and draft state; it does not style native tracks/thumbs or maintain DOM progress. The `FloatingToolbar`/`ToolbarGroup` surface, `ToolbarButton`/`ToolbarColorButton`, and `DropdownPanel` also come from Renderer UI, matching Editor icons, button states and dropdown motion. This consumer requires Renderer UI `^2.5.0` in both peer and plugin compatibility manifests. The shared package owns the slider CSS; the plugin continues to load only its own stylesheets.

`projectElementPropertyTarget` projects the same active/queued visual operations used by Canvas into the toolbar values. This includes pending font size, color and size; it never persists another copy of those values. Each number field synchronizes only when its own effective value or target identity changes, so unrelated color updates do not erase an in-progress size input. The Vue components connect controls to feature-local orchestration for field drafts, focus and popover lifecycle; value validation, color conversion and placement rules live in pure functions.

Toolbar content, popover geometry and custom-color CSS load through the plugin Renderer stylesheet contribution. Styles target only owned elements: a broad descendant `button` selector would override shared color cells and destroy their actual colors/selection feedback. Chrome uses Renderer UI semantic tokens; only actual slide colors and the color-plane coordinates own literal content colors. Shared UI internal selectors must not be overridden.

## Placement and interaction ownership

`SlideStage` mounts `ElementPropertyToolbar` as an absolute sibling of the scrolling canvas, within the existing stage pane. `useElementPropertyAnchor` converts the same presented selection bounds used by the outline, including Frame descendants, into pane-local CSS pixels. The toolbar does not participate in fit measurement. Scroll, zoom, viewport resizing and queued geometry updates refresh that anchor; no second selection store or hit test is introduced.

`elementPropertyToolbarGeometry` uses the measured surface size: center above the visible selected bounds, leave room for a hierarchy label, flip below when necessary, and clamp within the pane. For oversized selections it may overlap content; a fully offscreen selection hides it. Drag, resize and inline text input unmount the toolbar; release restores it from the immediate local preview without waiting for compilation.

The compact row shows font size and current text/fill colors only when supported, plus size and an icon-only delete action for every deletable target. Shared color buttons use the same compact width as ordinary icons, with no extra color-specific minimum width. One non-modal property popover opens at a time. Color uses the palette with a child custom-color form; size uses width/height inputs. A constrained root popover scrolls internally and stays above or below its own trigger. It cannot cover neighboring panes or alter canvas layout.

Group separators also belong entirely to Renderer UI: a 1×16px line with 6px of effective space on each side (4px group gap plus 2px line margin), shared with Editor text/table toolbars. Slides neither inserts another divider nor overrides the shared spacing.

`useElementPropertyToolbar` owns this instance's DOM measurement, selected property kind and numeric handoff. `BaseDropdown` owns outside-click dismissal and the remembered trigger; Apply/Escape uses its `closeAndFocus` public action. `DropdownPanel` owns surface, up/down 150ms motion and inert leave state; the same motion is used by CustomSelect. The BaseDropdown wrapper uses display:contents so it does not introduce a positioning or fit container. Before an outside pointer-down reaches the canvas, it blurs a focused owned number input so native `change` submits the draft to A before the same click selects B. It does not prevent that click or restore focus to A. The toolbar is keyed by author identity; changing target/page or leaving editing disposes the old popover. Async save responses do not close or refocus it.

The custom child uses the same shared `DropdownPanel` surface, motion and inert leave state. `useCustomColorSubmenu` owns only local hover/focus lifetime and DOM measurement; `customColorSubmenuGeometry` owns pure pane placement. A pane-sized, pointer-transparent overlay host lives inside the same BaseDropdown container. The child is teleported there to escape palette scrolling, while outside-click ownership and numeric handoff still recognize it as part of this toolbar. There is no body portal, global overlay stack or unrelated owner lookup. Positioning uses layout coordinates plus row-relative offsets so the parent entry animation cannot move the child anchor. Resize/mode changes remeasure actual dimensions.

The child prefers the right side, flips left near an edge, and aligns to the row top/bottom according to available height. In a narrow pane it may overlap the palette/toolbar; it remains contained and keeps Cancel and keyboard Escape available. It does not increase the parent palette height or change canvas fit. Hover departure waits 200ms for crossing the gap; entry cancels the timer. Focused inputs and explicit click/keyboard/plane editing keep the form open. Outside click still closes the whole property interaction without reclaiming focus.

Preset selection and custom Apply submit and close, returning focus to the toolbar trigger. Custom Escape cancels to the palette, including a hover-open child while focus remains on the parent; the next Escape closes the popover. Numeric Escape synchronously restores both the draft and native input value before blur, preventing accidental submission of a cancelled value. Delete/Backspace inside inputs or an open popover never deletes a canvas target; on a closed toolbar button, the explicit `delete-selected` event returns the intent to the existing Stage deletion owner. Shared `FloatingToolbar` does not swallow native input events or register global selection/keyboard handlers.

While a command or its target visual frame is pending, controls remain usable and emit typed intents into `manualEditing`'s serialized queue. Text style, fill, size and deletion are projected immediately from the active and queued values, then stay until each committed RenderModel revision is installed. Adjacent queued absolute changes for one target are coalesced to avoid redundant full compilation. A backend failure removes the active and queued projections and restores the committed pixels.

Tests in `functions/elementPropertyOperations.test.ts` cover target/capability boundaries and property value validation; deletion semantics stay with `manualEditing` and `editingInteraction`. `functions/hasElementPropertyControls.test.ts` verifies that move-only targets do not create empty UI while deletion-only targets do expose an action. Compiler, source-write, IPC and revision lifecycle coverage remains with their owning backend/shared features.

`projectElementPropertyTarget.test.ts` covers composed pending/queued text values and rollback; `customColor.test.ts` covers HEX/HSV round-trips and captured plane bounds. `useCustomColorDraft.test.ts` covers mode switching, invalid input correction and hue retention; `customColorSubmenuGeometry.test.ts` covers side flipping and narrow-pane containment. The `smoke:preview-transitions` browser fixture mounts this production toolbar alongside Canvas and resize handles, verifies preset/custom selection, invalid HEX, Apply/Cancel, independent numeric drafts and rollback, and captures light/dark/moon-blue themes after transitions settle. It exercises UI-to-intent/preview behavior; it does not replace full App Server save/reopen/export acceptance.

The same native smoke also mounts the production `SlideStage` and real edit queue: change A width then click B once, edit B while A is pending, coalesce standalone Text style, cancel numeric drafts, drag and restore from local geometry, zoom/resize the pane, navigate custom-color Escape levels, and delete from the returned toolbar trigger. Screenshots are written to `dist/dev/selection-property-toolbar*.png`. Geometry tests cover hierarchy spacing, edge flipping, oversized/offscreen selection and popover containment.

Native smoke also verifies an actual running dropdown transition, waits for that panel's animation before checking settled pixels, and treats an inert leaving panel as closed. The shared UI suite covers quick reopen, nested Escape, input focus and outside-click focus ownership.

Native custom-color checks use real hover across the menu gap and its close delay, keyboard opening, Escape from a hover-open child, RGB input/slider keys, mode switching, Cancel/reopen and exactly one Apply intent. Theme captures include both `manual-properties-{theme}.png` (HSV) and `manual-properties-rgb-{theme}.png`; they also show the action alignment. Narrow-pane smoke measures the actual custom submenu bounds.

The production toolbar fixture verifies icon-only deletion for all eight author target kinds, disabled behavior and capability admission. Production Stage native smoke deletes via both the keyboard and button, including consecutive Shape/Text deletion during pending submission, and checks one intent per target plus immediate selection cleanup.

The Stage smoke also exercises font-size preset selection by pointer and keyboard, focus return, min/max, fractional custom input, invalid/empty input, Escape cancellation and direct handoff to the neighboring color control while edits are queued. Font-size screenshots for all three themes are written to `dist/dev/font-size-toolbar-{theme}.png`. The range is read from the same `SLIDES_MANUAL_FONT_SIZE_PT` contract as operation validation, IPC admission and manual-edit persistence parsing.

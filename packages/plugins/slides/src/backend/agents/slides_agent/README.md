# Slides Agent 执行策略

Agent 定义装配工具白名单、必需的 slides-design Skill、模型上下文和步数策略。
设计与审批流程以 Skill 为准；这里不复制一份流程 prompt。

`executionPolicy.ts` 使用 Linnkit 既有 system-reminder 合同，在每 20 个图步骤的模型输入
中提醒复核阶段：调研/建稿/验收、完成页数、version、检查范围、P0/P1 与下一批动作。
task_write 保存进度；瞬态提醒不写成用户消息或第二份持久化状态。

退出准则：验收完成立即交付；两轮同范围检查无进展应重定位问题并合并修复；三轮无进展
应保留可用成果、说明具体阻碍，不谎称完成。P2 根据像素与设计意图判断，不能机械清零。
800 是复杂任务硬上限；剩余 60 步开始收尾提示，不改变用户审批条件。

这些是模型行为约束，不是确定性的无进展探测器。单元/集成测试只能证明规则确实进入
真实模型输入，不能证明所有模型都会遵循。收敛效果仍需用固定任务、固定模型、多次
真实运行对比完成率、总步数、重复编辑、成本与全页验收质量；不应只压低 maxSteps。

科研数据的来源、计算与视觉编码不变量，以及全页验收声明的证据要求，由 Skill 统一维护。
错误提示应帮助模型修正作者输入或识别平台阻碍，不能诱导其删除语义字段来通过检查。

## 输出边界

Provider adapter 负责把厂商推理与答案分别转换为 canonical `thought_delta` 和 `answer_delta`，
Linnkit 再持有两条独立事件流。Slides 不用 `<think>` 正则或逐 chunk 判断重新解释正文：标签
可能是用户要求展示的字面内容，网络分片也不是语义边界。Agent 使用基类的原样正文处理，
保持实时分片与持久答案一致；兼容特殊 Provider 协议必须回到 Provider owner，而非插件补丁。
真实 Slides Graph 回归同时验证完整/拆分标签正文、连续序号和独立推理事件不混入最终答案。

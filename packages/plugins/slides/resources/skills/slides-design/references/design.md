# Slides 设计判断

本文只提供设计建议，不定义工具、API、lint code 或质量阈值。运行时诊断与用户要求始终优先。

## 先确认视觉方向

新建文稿或整体改版的计划必须包含一份简短的 `visualDirection`。它回答“整份文稿为什么这样设计、如何组织视觉节奏、最值得记住什么”，与逐页内容一起由用户批准：

| 字段 | 要回答的问题 | 不应填写 |
|---|---|---|
| `concept` | 整稿遵循什么设计理念，为什么适合当前内容和受众？ | 只有“高级、简洁、有设计感”等空泛形容词 |
| `composition` | 使用什么构图、信息密度和跨页节奏？ | 每一页的固定坐标或成品模板 |
| `signature` | 全稿唯一的核心视觉记忆点是什么？ | 多种彼此竞争的装饰手法清单 |

视觉方向不是新的渲染字段，也不复制 `theme`。批准后，Agent 再把它落实为真实的颜色、字体、图表调色板、留白、构图和材料选择；局部编辑沿用现有文稿已经形成的设计系统，不重新发明方向。

## 先定视觉系统，再写页面

新建文稿或整体改版时，根据已批准的视觉方向，在动手写第一页之前定下这四件事，并把结论写进 `compose({ theme })`：

1. **主色与语义色**：一个主色，一到两个强调色，一组中性灰，以及含义稳定的语义色（例如"好/差"）。颜色一旦有含义就不要挪作装饰。
2. **字体**：标题族与正文族各一个（`theme.fonts` 要求两者同时提供）。文稿默认面向 Windows 与 Mac 的 PowerPoint，只从 CLI `fonts list --script <latin|eastAsian>` 列出的 Office 通用字体里选；PingFang SC、Songti SC 这类 Mac 专属字体会被 `font_not_deliverable` 报出。用户明确只在本机放映时，写 `theme.fontTarget: 'local'`，再用 `--target local` 查本机字体。
3. **背景基调**：浅底、深底，还是分区使用。深底要连带决定文字与图表的反白规则。
4. **图表调色板**：`theme.chart.palette` 按 series 顺序取色，整份 deck 共用一份。
5. **阅读方式**：`theme.reading` 写 `present`（讲的稿，投影给远处的人看）、`mixed`（边讲边发，缺省）或 `read`（发出去自己读，例如咨询报告、讲义）。它决定 inspect 的字号下限：以 13.333in 宽为准，正文分别不低于 18、14、12pt，10in 宽的稿子乘 0.75。图注和图上标签写 `role: "caption"` 或 `"label"`，脚注、来源、页码写 `"footnote"`、`"source"`、`"page-number"`，它们各有更低一档的下限；不写角色的文字按正文检查。
   阅读方式默认 `mixed`，写页面之前定下，之后不改。用户明确说稿子主要是投影讲给远处的人看时用 `present`；用户明确说是发出去自己读（报告、讲义、预读材料）时才用 `read`。用户没说，就是 `mixed`，投资评审、经营汇报这类数据多的稿子也一样。字号报错时拆页、换结构或删掉重复的话，页数可以比用户说的“左右”多两三页；不能靠改低阅读方式或缩小字号过检查。

这几项决定的是"这份文稿长什么样"，应当由内容和受众推出来，不是从示例里继承。示例中的颜色是那份示例的一次性选择。

**不要跳过 theme。** 它是跨页一致性的唯一依据：写进去的值会在后续编辑时通过 `DECK_DESIGN` 回到 source；不写则后续每次编辑都拿不到任何锚点。

## 叙事

- 先确定受众需要做出的判断或行动，再决定页面顺序。
- 一页承载一个主要论点；标题尽量直接表达结论，而不只是写主题名。
- 页面之间要形成因果、比较、递进或决策链，避免把资料按来源机械堆叠。
- 结尾应收束为结论、建议、下一步或需要批准的事项。

## 页面节奏

页面形式跟着这一页要讲的关系走：先后、对比、构成、因果、单个焦点，各自有合适的样子。页面大致有三种分量：

- **锚点页**：一个主视觉承担全部重量——大标题、整幅图片、单个结论级数字。封面、章节页、核心观点页属于这类。
- **密集页**：承载证据——图表、表格、多模块对比。允许信息量大，但仍要有明确的入口。
- **呼吸页**：留白、过渡、单句强调。它的作用是让前后两页的密集内容不至于连在一起。

页数跟着每页的字量走：字越少，页数越多。图像型、展示型稿子每页只放一个主角和一两句话，同样的内容就要摊成更多页，30 分钟左右的讲演通常要 30 页以上；把少字页压成十页上下，每页的主角会挤在一起，讲的人也接不上话。信息密的研究稿则相反，页数少、每页证据多。

连续几页长得一样时，先问它们讲的关系是不是真的一样：不一样就换表达，例如改成左结论右证据、整幅图片、单一大数字，或把并列改成时间、递进。

关系一样的一组页（几件器物、几个案例、几个实验）共用的是系统：标题位置、图注与参数的写法、字体和网格。构图不必共用，每页的视觉主角是这一件独有的看点，构图跟着看点走。下面几种只是例子，不是要轮换的版式：

- 看点是整体轮廓，就让器形占满一边的高度；
- 看点在局部（纹饰、扉棱、某个零件），局部特写当主角，全形缩成小图作索引；
- 看点是文字（铭文、手稿、实验记录），拓片或原件当主角；
- 看点是成组或尺度，就横向铺开，或放一个人、一只手作参照。

一组里每页都是“一侧参数、一侧整图”，通常说明还没找到每一件的看点。不要为了“换个样子”而换，也不要为了凑一种构图去增删内容。[`card-grid.js`](./examples/card-grid.js) 的最后一页是同样内容换构图的对照。

## 信息层次

- 先让读者在数秒内看懂标题和主视觉，再阅读证据与说明。
- 重点通过尺寸、位置、留白和对比建立；不要同时依赖过多颜色、粗体、描边和图标。
- 卡片行需要主次时，优先改 flex 权重让主项占更大面积，而不是给它换一个更艳的颜色。
- 数据页先写结论，再展示支撑数据。选图之前先问这组数据要说什么关系：比例、变化、构成、对比还是规模。关系定了再选形式，不要默认“三个大数字 + 一张条形图”；规模感强的数字可以换成实物比例图，精确查数才用表格。
- 正文应短而完整。内容放不下时拆页或换表达，不靠持续缩小字号解决；删减只删重复和空话，不删计划里的要点。

## 跨页一致性

- 全 deck 复用少量字体、颜色、标题层级、网格、边距和组件样式。
- 建立主色、中性色和少量语义色；颜色应有稳定含义。逐页轮换不同色相的淡底色，和彩虹淡底卡是同一种模板感；底色变化只用来分章节或分页面类型。
- 同一类页面使用同一标题位置、图表规则、页脚和来源格式。
- 局部编辑沿用现有设计系统；除非用户要求，不因单页问题重做整份文稿。

## 视觉材料

每页先定靠什么说话，再写字。视觉主角可以是照片、插画、图解、图表、大数字，也可以是排版本身；定下来以后，字只补主角说不出的东西。

- 内容离不开具体对象（器物、人物、现场、实验装置、产品）时，先把这些图找齐再排版，找不到再换讲法。去哪找见 [`assets.md`](./assets.md)。
- 每张图做一次诚实性测试：拿掉它，这页的信息有没有损失？没有就是装饰，不放。
- 展示型稿子每页正文不超过 80 字，放不下就拆页。
- 图片必须服务于信息：建立情境、解释对象、展示证据或加强记忆。
- 使用真实且可访问的资产，避免捏造图片、logo 和来源。引用不存在的图片会让编译直接失败。
- 图片放进版面前先想清楚它承担什么：全幅主视觉、并列证据，还是退到背景。全幅图片上放文字时必须加遮罩层，否则对比度不可控。
- 需要改变图片本身（裁切比例、缩放、换格式）时用 Shell 预处理，再引用产物；`fitMode` 只决定图片如何放进盒子，不改变图片。
- 复杂流程、架构或机制关系如果用大量 Shape/Line 难以稳定表达，且只需整体移动、缩放和替换，可以使用 SVG Graphic；标签和解释文字仍用原生 Text。简单几何、真实数据图表和需要逐项编辑的对象不要转成 SVG。
- 渐变、自定义几何和圆形遮罩是可用能力，但它们服务于结构表达（分区、指向、层次），不是用来填补空白。装饰不能盖过内容或制造假数据感。
- 对比度、字号、色觉可辨识和图表标签应照顾真实演示环境，而不只适配编辑器近距离查看。

## 中文排印

- 正文一行 22–38 个字，28–32 最好读；行高 1.5–1.8，比西文高一些。
- 正文字距 0 到 0.05em；标题不要收紧成负字距。
- 中文不用斜体，强调靠字重、颜色或位置。
- 竖排是中文独有的手段，适合题签、目录、侧栏和短句，不用于长段正文。

## 封面

先写钩子，再选构图。钩子从材料里取：最强的结论、一个隐喻、一个数字、一个时刻或一个冲突。封面要让人一眼知道这份稿子凭什么值得看，而不只是标题加一张好看的图。

下面是一些搭法，只作参考，不是清单。按钩子和手上的素材挑；素材撑不住就换，也可以做表里没有的。

| 搭法 | 适合的钩子 | 要什么素材 |
|---|---|---|
| 字体主导：巨大标题、大留白、细线 | 一句有力的结论 | 好的标题字体；不要图 |
| 全幅主视觉：整图加遮罩、反白标题 | 一个时刻、一处现场 | 1920px 以上、有安静区域的原图 |
| 一个数字：结论级数字占满视线 | 一个数字 | 可核对的数据来源 |
| 编辑出版：多栏网格加规则线 | 一份观点、一份报告 | 几段真实的导语 |
| 色块宣言：渐变或几何色块，文案极短 | 一句口号、一个愿景 | 不需要图 |
| 书法大字加去背实物 | 一件代表器物或作品 | 去背干净的主体、书法字 |
| 框景：主体放进海棠窗、月洞门、拱门 | 一处景、一件物 | 能裁进形状的图 |
| 破框主体：主体越出画框或压住标题 | 一个有力的对象 | 去背主体 |
| 竖排题签加印章 | 典籍、书画、节令 | 竖排标题和一枚印章，留白就是画面 |
| 出血拼贴：几张图越出页边错落叠放 | 一组对象、一段历程 | 3 到 6 张风格相近的图 |
| 斜切分屏：两种画面沿斜线相接 | 对比、转折 | 两张能对照的图 |
| 局部特写满版 | 纹样、质地、细节本身就是主题 | 裁切后仍有 1920px 宽 |

[`cover-variants.js`](./examples/cover-variants.js) 是前五种的代码写法，只示范能力，颜色和尺寸不要照抄。

左边标题、右半边一张图，是模型最熟的封面，多次测试里大多数稿子都落到这里；满版图上把标题压在左边，也是同一个结构。调用过 `ppt_direction` 时，按方向说明里的“封面构图”安排标题与主体的位置，再从上表挑贴合钩子的搭法。

## 默认样子要自觉

模型最熟的样子是：暖奶油底、高反差衬线标题、陶土色点缀、全大写的小标签、01/02/03 编号。它们不是错，但只在题材需要时用；每次都出现，就成了一眼能认出的模板。每页标题都钉在左上角也是一样：章节页、金句页、大数字页和满版图页，标题可以放在构图需要的地方。

母题负责让人认得出主题，不负责把每一页做成道具。整页做成地铁线路图、档案柜、仪表盘这类隐喻，往往盖过内容；隐喻用在封面、章节页和一两处细节上就够了。

## 风格方向

| 风格方向 | 适用场景 | 主要特征 | 注意事项 |
|---|---|---|---|
| 咨询/董事会 | 决策、经营复盘、方案比较、投研 | 结论型标题、严谨网格、数据与行动优先；做法见 [`style-consulting-report.md`](./style-consulting-report.md) | 不要把每页都塞成密集表格，也不要每页重复同一种提示条 |
| 产品/科技 | 产品路线、技术方案、发布 | 清晰系统图、深浅层次、少量高亮 | 不要用装饰性"科技感"取代结构 |
| 编辑/出版 | 观点、报告、内容型叙述 | 多栏网格、规则线、克制的强调色 | 栏目要有真实的信息分工 |
| 创意/品牌 | 提案、故事、活动、愿景 | 强主视觉、节奏变化、简短文案 | 风格变化仍需共享字体和色彩系统 |
| 学术/研究 | 方法、证据、发现、局限 | 来源清楚、图表可读、结论克制 | 不要把论文段落原样搬上页面 |

表中的风格方向是判断参考，不是可选模板列表。同一个风格方向在不同任务下应当有不同的颜色、字体和版面。

### 手绘材料的构图顺序

使用 Brush 时，先用 `watercolor`、`wash` 或 `mass` 建立大色块、轮廓和画面重心，再用 stroke 补充枝干、边缘与节奏，最后只在局部需要纸面质感或方向强调时使用 hatch。复杂画面应拆成多个语义图层，例如“远景色块 / 主体轮廓 / 花叶细节 / 局部纹理”，而不是用一种笔刷铺满全页。`field` 用来改变笔触走势，不是随机装饰；文字、数字、标签和公式始终保留为原生对象。Brush 产物不透明，选择背景色时必须把它视为构图的一部分。

## 可复用版式模式

- 极简叙事：大标题、单一焦点、充足留白，适合封面、章节页和核心观点。
- 高管摘要：结论标题、关键指标或 2–4 个证据模块，适合进展与决策页。
- 数据分析：结论、主图表、必要注释和来源，适合趋势、比较和构成。
- 路线图：阶段、时间、责任或产出形成单一阅读方向，适合计划与实施。
- 对比矩阵：维度有限、标签清楚、重点突出，适合方案选择。

这些模式描述的是结构，不是成品。同一个模式可以有完全不同的视觉表达；[`cover-variants.js`](./examples/cover-variants.js) 展示了同一个"封面"需求下五种结构不同的解法。

## 高频问题重点复核

多轮真实长稿测试反复出现以下问题。完成前必须按顺序在最终 revision 的渲染图片中逐项检查，不能用 source 推断、`inspect` 通过或最终回答中的自述代替像素判断。先处理断行、字号、遮挡及图表语义等确定性问题；卡片节奏等审美问题只有明显不合理时才修改。任何修改都必须在新 revision 上重新 render，不能沿用修改前的判断。

1. **非预期断行**：重点查看页码、序号、短标题和表格窄列。原本应保持单行的短文本不要放进过窄的固定宽度；需要自动换行的正文则为真实字体宽度留出余量。
2. **字号过小**：重点查看正文、来源和脚注。内容放不下时拆页或换结构，不靠持续缩小字号解决；删减只删重复和空话。
3. **遮挡、裁切与贴边**：重点查看长标题、卡片底部、图表标签、页面四周，以及页码、页眉、页脚等固定元素，确认文字没有越出容器、被图形遮住或贴近裁切边界。
4. **图表语义不足**：图表必须真正支撑标题结论；根据表达目的检查数值、单位、尺度、标签和图形关系是否齐全，不能只做出某类图表的外形。
5. **卡片堆叠与模板感**：避免连续页面重复使用卡片网格。根据内容关系改用主图、表格、矩阵、流程、时间轴或重点数字，并为整份 deck 保留构图节奏。每页都出现、位置固定的提示条（反证、风险、结论）同样是模板感，只放在真需要的页。卡片或提示框左侧加一条竖色条、顶部加一条色条、彩色淡底卡配同色描边，是一眼就能认出的 AI 模板写法，不要用；要区分主次就改面积、位置、字重或留白。
6. **对比只给一张表**：几样东西放在一起比，而它们本身有样子（器物、产品、建筑、作品），先给图：图卡并排，图上叠由透明到不透明的渐变，名称和一句特征压在渐变上；一页放不下就拆两页，表格只补图上放不下的细节。
7. **少字但空洞**：展示型稿子每页字少，但这些字只写某类东西的常识（“鼎有三足两耳”），图也只是一张整图，就成了普通陈展。字要写这一件东西的具体信息和独有看点，再用局部特写、标注和编号把细节讲出来。
8. **表格默认样式**：原生 Table 不设样式时是灰表头、白底正文，和主题无关，放在有底色的页面上像贴了一张白纸。每张表都要按主题设计：表头逐格 `fill` 用主色或主题的深色并配反白字，或用页面底色加粗字配一条主色细线；正文逐格 `fill` 用页面底色，行间用主题色极浅一档隔行；字体、字号、颜色与正文一致，数字右对齐。整稿的表格用同一套写法。渲染后看表格有没有像白纸一样浮在页面上、行与行能不能分清，`border` 设了以后也要在像素里确认线确实画出来。

## 质量诊断会看哪些维度

`inspect` 的阈值以运行时输出为准，本文不复制数值。但知道它测量什么，可以让这些判断发生在写代码之前而不是之后：

- **跨页重复**：按结构指纹比较相邻页——元素类型、区域、尺寸与跨度的组合。颜色不同但结构相同不算不同。
- **主色漂移**：跨页主色的色相离散程度。每页换主色会被捕捉到。
- **单页色彩发散**：单页非中性色的色相簇数量。
- **字体族数量**：整份 deck 使用的字体族总数。
- **字号档位**：单页字号的层级数量，以及是否存在过小的字号。
- **视觉锚点**：页面是否存在一个主导元素或标题级文字。均衡布局是合法选择，这一项只是提示。
- **文字对比度**：文本与其底层填充的对比度。
- **图片比例**：拉伸导致的宽高比失真。
- **边缘留白**：非全幅元素与画布边缘的距离。

诊断只保证"不明显出错"，不保证"设计得好"。全部通过不等于这份文稿值得交付；真正的判断仍然是：读者能不能在该看到的地方看到该看到的东西。

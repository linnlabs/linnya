# Canvas 批量写入准备

`prepareCanvasWrite` 将模型操作转换成正式逐元素命令，事务外调用正文解析、文档定位、图片准入和一次批量真实测高。调用方提供作用域与资源 ports；本 feature 不读取 Host 表、不写数据库，也不决定审批。最终位置、字段版本、编辑保护和原子性仍由 `canvasCommit` 决定。

模型原始批次最多 500 个动作，`arrange` 只能放在最后；一次排布或大选区操作会展开为更多元素更新，内部提交不机械套用该模型输入预算，不拆成半成功的批次。自动文字高度上限为 1800 世界像素，固定高度继续保留。`append` 的原始身份必须在准备前经 Agent 回执重放检查，不能以当前正文再次归一化来判断重试。

`shared/cli` 是原始操作 schema 的唯一 owner。CLI parser 只形成命令和访问计划；资源读取、写入、worker 与受管文件交付由插件组合层装配。

已有连线的label/direction/lineStyle/linePattern由update原位修改，保留连线ID与端点；用于卡片会在准备阶段明确拒绝。方向和样式沿共同提交既有的后写生效规则，标签沿读版本保护，编辑声明、旧实例保护与撤回记录仍由同一提交owner处理。更新省略样式不注入创建时的默认值，不用断开重连绕过字段归属与历史。

准备流程按业务数据流组织：单动作编排分别处理卡片新增、现有元素更新与纯连接/删除；属性patch由纯规则检查目标类型，文字更新单独协调替换/追加解析。追加仅解析新块并保留原canonical标签与图片身份。所有自动文字测量先收集到同一批，provider完成后按命令位置统一回填高度；固定高度不参加测量，缺失测量结果直接失败。外层编排负责取消与原始操作序号，不在其内复制字段规则。

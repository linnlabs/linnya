# Canvas 当前内容提交

本 feature 拥有元素行、字段来源/版本、分配计数、内容序号、正式请求回执和短期同步日志。同步日志另供只读的“某序号以来的变化”查询（`readCanvasChangeLog`），裁剪后由查询方报不完整，不承担撤回或历史记录。用户撤销栈、Agent 组和长期版本分别由其他 owner 持有，组合层将其作为同事务参与者接入。

`planCanvasCommit` 只组织纯计算步骤：卡片/连线创建、既有元素变更、最终图校验和布局障碍避让。创建规则在 `createCanvasElements`，更新与删除的锁定、编辑声明及字段冲突规则在 `mutateCanvasElement`；`canvasPlanChanges` 统一维护本批元素与字段来源。可变工作集合只在一次纯计划计算内存在，不是运行态 store。

用户可用精确坐标，Agent 只能使用相对放置。避让仅扩展新卡的放置方向，不移动既有卡。布局更新还依赖测量时尺寸；后来长高、锁定或被编辑保护的卡保留原位。文字、颜色、位置等字段独立判断陈旧写入。删除卡片与附属线在同一批计划内完成，最终图不能留下悬空依赖、同方向重复线或非法分区归属。

Agent 删除和断开连线必须提供读取时的revision；Core缺失基线返回`revision_required`，陈旧基线返回`stale_element`，不删除用户的后写。用户界面仍可删除当前选区。同方向重复connect只跳过该条并返回`connection_exists`及原线ID，不覆盖原线内容、不消耗新ID，也不拒绝同批其他合法操作；后续ref可指向该原线。自连线、悬空端点、无效放置目标和分组错误返回稳定的`CanvasCommitFailure`错误码与安全说明，不掩盖成未知运行错误。

`commitCanvasTransition` 在同步 SQLite 事务内依次验证回执、读取严格当前状态、计算计划、保存内容与回执、调用参与者和历史钩子。任何参与者失败都回滚；内存栈更新与发布发生在提交之后。回执重试不能再次执行计划，异载荷复用编号必须拒绝。已提交后的通知失败只报告，不伪称内容未保存。

`canvas_requests`是用户与Agent唯一的回执owner：成功提交、待确认及拒绝/替换/撤回/完成状态共用同一请求身份，正式结果不在Agent表重复存储。每张画布保留最近1000条未固定的终态回执；pending及未结束组明确引用的跳过结果另行固定，组完成后释放并立即裁剪。普通成功回执不是撤回依赖，不因组一直未关闭而无限保留。终态替换取得新的插入次序，长时间等待的审批也得到完整重放窗口；没有表依赖内部rowid。清理和正文、审批、组状态在同一事务，失败一起回滚，不影响其他画布。

幂等重放只承诺回执仍在保留窗口内；超窗查询返回null，不代表从未执行。调用方须读取当前内容并确认原意图结果，不得盲目重发旧新增/追加。`queries.ts`仅导出只读查询，独立CLI不装载提交、审批及回执清理函数。

元素 revision 与字段版本单调增加；逻辑来源可由撤销恢复。文档 `maximumRevision` 是恢复已删除旧身份的修订下界，不能因 guard 清理或历史恢复下降。新卡/线分配计数永不倒退。显示用的只读隔离投影不得进入本 feature 的写状态，损坏或未来格式由严格读取拒绝。

内容push携带事务结束后采样的UTC毫秒committedAt、来源类别与实际改变的元素数，供端到端观测关联序号与真实变化帧。它不是请求开始或Worker完成时间；消费者不能用SSE接收时间冒充提交时间，也不能把只改视口外元素的首帧说成全部可见内容更新。相机和这些诊断事实不进入文档内容或版本历史。

## 分区

分区是 `type: 'section'` 的卡，成员用 `parentId` 指向它，只有一层：`parentId` 只能指向分区，分区自身的 `parentId` 必须为空，违反时返回 `canvas_section_parent_invalid`。`fitCanvasPlanSections` 在最终图校验前按序处理同批计划：只改归属、没给位置的卡（Agent 不能给坐标）由程序挪位，放进分区排到区内空位（`placeCanvasCardInSection`），移出却仍压在原区上就挪到原区右侧；被删分区的成员清空 `parentId` 并留在原位；每个分区只向外长到包住全部成员加内边距，不自动缩小。这些附带修改并入同批已有变更，不额外增加修订或回执项。

`add type:section` 带 members 时围着成员建区、成员不移动；布局清障时移动卡所在的分区不算障碍。连线不属于分区。

## 同条更新的字段结果

每个原操作仍返回一条结果。`fieldResults`记录本次实际接纳/跳过的字段和原因；至少一字段接纳时操作为`applied`，混合结果附`partial_fields_skipped`。实体级历史反转没有此成员时表示字段细节未知，不补空数组、不用原patch猜；这不是旧格式回执兼容。正式用户会话先同步实际子集，再对任何跳过字段抛出`CanvasCommitOutcomeError`，避免把部分成功当成已保存全部草稿。

元素不存在或锁定仍整条跳过。任何update先验证`$existence`世代：删除后历史恢复的同ID不能接受旧实例写入。颜色、层级、箭头方向、曲直和线型按后写生效；正文data、线标签、几何和锁定仍校验读取版本，编辑声明优先于样式后写。用户只能用原有单独解锁动作解除锁定，不通过混合patch绕过。

语义单元只绑定实际依赖：自动文字正文/宽度/高度共同接受或跳过，并校验未写入的正文/宽度/高度依赖；裁剪或资产替换与同条图片frame共同处理；二维位置、成对尺寸和交换的两端点各自成组。布局XY还校验尺寸及其编辑声明。独立颜色始终在这些组之外。data保持完整结构化字段，不递归猜测JSON子字段合并。

编辑保护由每个Renderer视图统一拥有owner并集与一个2秒续约器；一次IPC原子替换当前整组声明，500卡拖动不逐卡发送。数据库仍按10秒期限判断有效声明，领取/释放串行且同task合并，关闭先失效旧世代并等待已投递写入，再释放视图。

元素写入语句在单次提交内编译复用，删除前值预先建立索引；新元素使用本批最高order继续分配，包括连线，避免逐次全量排序。引用/资产只比较本批元素的原始和最终资源身份，移动、染色不重建关系或登记全部资产；真正改变关系时仍由Host owner在同一事务准入并按差异写入。

每个成功操作只增加一次元素修订；仅接纳字段更新fieldVersions/fieldOrigins，历史/组只记录实际变化。布局清障的moved集合只来自实际既有元素位置更新，不能因同条颜色成功或新建卡的初始XY而绕过位置保护。非法正文/格式与最终图不变量仍整批回滚。

正文JSON（含attrs/marks）的结构深度上限128，与宿主传输边界一致；入口先迭代检查，再进入递归schema。超限返回验证错误，不能以RangeError冒充未知执行失败，也不会半提交前面的合法操作。原始CLI操作条数仍为1～500；Core可接纳排布展开后的完整批次。

# Canvas 当前内容提交

本 feature 拥有元素行、字段来源/版本、分配计数、内容序号、正式请求回执和短期同步日志。用户撤销栈、Agent 组和长期版本分别由其他 owner 持有，组合层将其作为同事务参与者接入。

`planCanvasCommit` 只组织纯计算步骤：卡片/连线创建、既有元素变更、最终图校验和布局障碍避让。创建规则在 `createCanvasElements`，更新与删除的锁定、编辑声明及字段冲突规则在 `mutateCanvasElement`；`canvasPlanChanges` 统一维护本批元素与字段来源。可变工作集合只在一次纯计划计算内存在，不是运行态 store。

用户可用精确坐标，Agent 只能使用相对放置。避让仅扩展新卡的放置方向，不移动既有卡。布局更新还依赖测量时尺寸；后来长高、锁定或被编辑保护的卡保留原位。文字、颜色、位置等字段独立判断陈旧写入。删除卡片与附属线在同一批计划内完成，最终图不能留下悬空依赖、同方向重复线或分组环。

`commitCanvasTransition` 在同步 SQLite 事务内依次验证回执、读取严格当前状态、计算计划、保存内容与回执、调用参与者和历史钩子。任何参与者失败都回滚；内存栈更新与发布发生在提交之后。回执重试不能再次执行计划，异载荷复用编号必须拒绝。已提交后的通知失败只报告，不伪称内容未保存。

元素 revision 与字段版本单调增加；逻辑来源可由撤销恢复。文档 `maximumRevision` 是恢复已删除旧身份的修订下界，不能因 guard 清理或历史恢复下降。新卡/线分配计数永不倒退。显示用的只读隔离投影不得进入本 feature 的写状态，损坏或未来格式由严格读取拒绝。

内容push携带事务结束后采样的UTC毫秒committedAt、来源类别与实际改变的元素数，供端到端观测关联序号与真实变化帧。它不是请求开始或Worker完成时间；消费者不能用SSE接收时间冒充提交时间，也不能把只改视口外元素的首帧说成全部可见内容更新。相机和这些诊断事实不进入文档内容或版本历史。

# 当前卡片内容投影

`createCanvasCardContent` 只持有可销毁的资源与身份缓存，不拥有正文或项目事实。受管图片正文只保存 assetId 与 asset: 源，读取后的 data URI 仅进入 DOM；图片缓存有 32MiB 上限。静态 DOM 与后台 worker 共用 cardRendering/content 的资产和标签水合函数。

内容入口组合引用身份、图片、文档预览和通知；`createCanvasContentNotifications` 独立持有通知计时与订阅。文档预览入口只协调读取与世代重验，`createCanvasDocumentPreviewCache` 拥有有界 LRU 结果及缩略图呈现事实，`createCanvasPreviewInterest` 拥有当前可见需求与预读游标。可见兴趣去重和缓存淘汰是不同生命周期，不能合成同一个集合。

文档卡及正文标签通过通用 documentReferences 查询当前身份；搜索预读全部引用目标，最多 8 个并发，不只读取视口中的目标。Workspace 正式 mutation 和 pluginRuntime 启停通知失效相关身份，世代进入正文位图键，迟到的旧请求不能覆盖当前标题。跨项目与删除状态移除标题，不能继续被搜索命中。消费者用 subscribe 重新调度受影响正文，关闭时 dispose 释放订阅和资源。

可见文档预读记录按项目、目标身份世代及宽度保留。单个目标变代只移除它的旧记录，离开视口才移除对应兴趣；不能因其他文档身份返回而整体重置。完成预读的身份即使被128项/32MiB结果缓存淘汰，也不在同次可见期间反复预读；真正需要正文或打开详情时仍可按需读取。

已知引用在并发查询前统一登记初代，后续结果只补当前身份，不反复改变世代。可见数组、项目和整组世代未变时，预读游标继续剩余目标，不重新扫描已访问前缀；真正的Workspace/插件失效、几何可见集合变化和显式重试仍重新复核对应需求。

已完成资源在8ms短任务窗口内合并内容通知，读取队列继续独立推进，不让每个结果都触发全视口正文需求扫描。资源编排不进入纯绘制RAF闭包。身份失效仍立即通知以清除旧标题/位图，错误也立即报告；关闭释放尚未发出的成功通知，历史预览与正式表面共用同一规则。

预读、可见正文和打开详情共用4个Host预览传输槽位；显式按需读取优先等待槽位，不绕过上限。槽位只覆盖实际`port.preview`请求，结果世代重验及重读在释放后进行，避免多个旧结果等待自己的新请求。关闭拒绝尚未发送的读取，在途结果继续遵守既有失效检查。

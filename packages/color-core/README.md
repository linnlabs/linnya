# Color Core

`@linnya/color-core` 是仓库里颜色运算的唯一 owner：颜色解析、sRGB / 线性 sRGB / OKLab / OKLCH 互转、色域处理、混色与 WCAG 对比度。它不读文件、不存数据、不认识图表、文档格式或插件；同样输入得到同样输出，Renderer、App Server、Worker 和插件都可以直接引用。

先例是 `@linnya/text-measurement-core`：业务包只保留自己的规则和阈值，不再复制颜色公式。

## 口径

| 项 | 口径 |
| --- | --- |
| 色相、彩度 | OKLCH（Björn Ottosson 公式） |
| 对比度 | WCAG 2.x 相对亮度；sRGB 线性化阈值 0.04045，对 8 位通道与 WCAG 文中的 0.03928 结果相同 |
| 解析 | `#RRGGBB`、`#RGB`、`rgb()` / `rgba()`；其他写法返回 null，不猜颜色 |
| 输出 | `toHex` 取整并截到 0–255，输出小写 `#rrggbb` |
| 色域 | `oklchToRgb` 超出 sRGB 时按 CSS Color 4 映射：保持明度与色相、二分降低彩度，剪裁误差小于 ΔEOK 0.02 即停。低彩度时这点剪裁会让色相偏几度，按色相判断颜色关系的调用方传 `{ jnd: 0 }`，只降彩度、明度与色相严格不变 |
| 色差 | ΔEOK（OKLab 欧氏距离） |
| 色觉异常 | Machado、Oliveira、Fernandes 2009 严重度 1.0 矩阵，作用在线性 sRGB 上；是最坏情况 |

## 公开入口

- `parseColor`、`toHex`、`mixColors`、`withAlpha`
- `rgbToOklab`、`oklabToLinearRgb`、`oklabToOklch`、`oklchToOklab`、`rgbToOklch`、`oklchToRgb`、`isLinearRgbInGamut`、`srgbChannelToLinear`、`linearToSrgbChannel`
- `relativeLuminance`、`contrastRatio`、`deltaEOK`
- `maxSrgbChroma`（给定明度与色相的 sRGB 最大彩度，用于相对彩度）
- `normalizeHue`、`hueDistance`、`isHueWithinArc`
- `simulateColorVisionDeficiency`、`COLOR_VISION_DEFICIENCY_MATRICES`（矩阵也可直接用于 SVG `feColorMatrix`，其默认在线性 RGB 中运算）

## 取色与配色：`@linnya/color-core/palette`

`suggestPalettes(input)` 从调用方解码好的图片（RGBA，建议长边 128 px，最多 20 张，第一张是主图）和/或种子色出发，返回题材本色、中性色候选、排除的色相区间和若干套配色。它不解码图片、不读文件；图片怎么来由调用方决定。Agent 做一份稿子时，把为整套稿子收集的图片一起传入，不是一张图出一套色。

每套配色有 `bg`、`surface`、`ink`、`muted`、1–6 个 `accent` 和 5 档 `chart`。强调色个数由调用方用 `accentCount` 指定，对应 PowerPoint 主题的 accent1–6；不传时按搭配关系默认 2–4 个。

1. **量化**：每张图在 33³ RGB 直方图上做 Wu 量化，再在 OKLab 里做按像素数加权的 k-means。画面中心的像素权重为 1，边角降到 0.5。
2. **找本色**：彩度太低或过暗过亮的颜色只算中性色。彩色按色相聚成族（种子色相 ±18°，族不沿色环漂移）。
   - 代表色分开平均明度与彩度，色相按“占比 × 彩度”求圆形平均。
   - 打分以占比为主，出现在几张图里和接近目标彩度为辅；只在一张非主图里出现的降权。主图至少占全部权重的四分之一，不被其余图片稀释。
   - 最多选 4 种本色。彼此色相相差 30° 以上；相差 10°–30° 时 ΔEOK 须 ≥ 0.2（如铜褐与亮金）；相差超过 144° 的落在对侧，不与已选的同稿。
   - 另取最多 2 种**点缀色**：面积小（≥ 0.4%）但鲜明（彩度 ≥ 0.08）的颜色，按“占比 × 彩度”排序，取族里最鲜明的那块实际颜色，标 `spot: true`。
   - 点缀色只做搭配色，不当主色。给了 3 张以上图片时，只在一张图里出现的本色也只做搭配色：多半是某张图的背景或灯光（如光合作用主图背景的暗红），整套铺成它就离题了。没有一种本色出现在两张以上的图里时，出现次数分不出主体和背景，这条不生效，只限制点缀色。
3. **排除区**：每种本色对侧 150°–210°，加上 `avoidColors` 两侧各 30°。相隔不超过 12° 的两段合成一段。
4. **风格基因**：一套配色由几维组成。
   - **搭配关系**，参照 PCCS 的色相关系：
     - 同色系：只用主色，靠色调拉开。
     - 灰 + 主色：近中性的纸与灰阶，只有主色有彩。
     - 邻近色（色相差 25°–50°）、中差色（60°–105°）、对照色（110°–144°）：搭配色优先取图片里色相差落在区间内的本色，没有再合成；合成的色相差不超过 128°，不做补色。
     - 多色：至少有 3 种本色时，从图片本色里随机挑看得出不同的颜色，一套最多 3 种。
   - **底色明暗**：浅底、染纸、深底。
   - **底面变体**：浅底有带本色、偏冷、纯白三种，染纸有淡、纸两种，深底有近黑和本色深底（藏青、墨绿一类）两种。
   - **色调**，借鉴日本色研 PCCS：浅底与染纸上有本色、柔、浊、深、暗、强、灰，深底上有本色、浅、柔、明、灰。色调用 OKLCH 明度加相对彩度定义，相对彩度 = 彩度 ÷ `maxSrgbChroma`，同一档在不同色相上看起来一样鲜。
   - **强调色**：按色相轮流取，色相用完后换下一档色调（tone-on-tone）。彼此 ΔEOK 至少 0.07（按写出的 sRGB 颜色算），太近时沿明度拉开。
   - **图表**：单色相时明度单调、色相缓慢漂移（Cubehelix 的思路）；多色相时各色相沿色环排好、主色打头（最显眼的一档），按明度单调渐变；灰 + 主色时主色打头，其余是灰阶。
5. **采样**：每次按先验权重采样 240 个候选，先验只决定出现频率。生成时检查：
   - **对比度**：在期望明度附近二分查找，保证 `ink` ≥ 7:1、`muted` ≥ 4.5:1、每个 `accent` ≥ 3:1（对 `bg`）。
   - **看得出不同**：不同色相的强调色之间，色相差在 OKLab 里（ΔH = 2√(c₁c₂)·sin(Δh/2)）至少 0.035。灰绿配灰青这类色相差 40° 但彩度只有 0.04 的组合，看起来仍是一种颜色，丢掉。
   - **图表系列**：按明度单调排列；浅端彩度减半，避免糖果色。
   - **排除区**：所有有彩颜色都避开排除区，并留 6° 余量。
   - **底色**：染纸避开 45°–100° 的米色带，彩度不超过本色彩度的一半。
   - 不合规的候选直接丢掉。
6. **评分**：显式规则的系数之积。以下情况降分：
   - 暗黄绿：Palmer–Schloss 2010，阈值同 Material DislikeAnalyzer，换算到 OKLCH。
   - 强调色与墨太近。
   - 图表相邻两档太近。
   - 有彩底配高彩强调色。
   - 三种以上色系且强调色平均彩度高于 0.1：彩虹感。
7. **按差异挑选**：用 `paletteDistance` 衡量两套的差异，以**色系组合**为主。
   - 色系按 OKLCH 色相粗分为红、橙、黄、绿、青、蓝、紫、品红；暖色相里偏暗或偏灰的算褐，暗的黄绿算橄榄（`colorFamily`、`paletteFamilies`）。
   - 距离 = 两套色系集合的 Jaccard 距离 + 底色明暗不同时加 0.25 + 0.5 × 角色加权 ΔEOK。只换深浅的几套色系相同，算作相近。
   - 第一套从高分段里按分数加权抽。之后每套与已选各套的距离不低于门槛：从 0.7 起，逐步放宽到 0。满足门槛的候选里优先没用过的关系，再按分数加权抽。
   - 这是 O'Donovan 2011 给多条建议的做法，相当于贪心 MMR。
8. **可复现**：结果编号（`pl` + 4 位 base36）就是随机种子。同样输入加同一 `rng` 结果逐字节相同；不传则每次不同。

生成颜色时用 `oklchToRgb(..., { jnd: 0 })`：严格保持色相，排除区判断才可靠。取色本身是确定的，随机只用在采样风格基因和挑选上。黑白图、拓片取不出彩色时返回 `{ kind: 'no_subject_color' }`，不编造颜色。

常量集中在 `src/palette/definitions/paletteConstants.ts`，数值来自三组真实用图（20、10、6 张）的离线样张。改动前先重出样张对照。

三组真实用图各跑 100 次（每次 3 套）的结果：

| 用图 | 色系组合 | 一次 3 套色系组合都不同 | 单一色系 | 两种色系 | 三种及以上 |
| --- | --- | --- | --- | --- | --- |
| 青铜器（5 种本色，含 2 种点缀色） | 30 种 | 100/100 | 36% | 44% | 20% |
| 光合作用（3 种本色，暗红只在主图里） | 18 种 | 100/100 | 35% | 49% | 16% |
| 储能（1 种本色加 1 种点缀色） | 7 种 | 100/100 | 29% | 71% | 0% |

只有一种主色的用图，搭配色多是合成的，组合自然少。一次取色加出配色约 13–41 ms。

### 用户指定颜色

`suggestPalettes({ pinnedColors })` 接受 1–6 个用户指定的颜色，第一个是主色。

- **色值不变**：3 套的前几个强调色就是这些色值。强调色个数少于指定色个数时，按指定色个数算。
- **对比度靠调底色**：指定色对底色不到 3:1 时，沿离开它的方向调底色明暗，调到头仍不够就放弃这个候选。浅黄只会出深底，藏青只会出浅底或染纸底。
- **排除区以指定色为准**：色相差超过 144° 的图片色被丢弃，其余仍可做搭配色。包含指定色相的排除段作废，所以两个指定色互为对侧、`avoidColors` 压到指定色时，仍按用户说的做。
- **多个指定色**：搭配关系由它们的色相差决定；后面的强调色多数时候借一种图片色。图表只用指定色的色相轮流，不沿色环插值。
- **失败**：黑白灰没有色相，返回 `{ kind: 'pinned_color_neutral', hex }`；要求的底色上做不到对比度时返回 `{ kind: 'pinned_color_conflict' }`。

### 检查一套自写的配色

`checkPalette({ palette, excludedHues, pinnedColors })` 检查不是算法生成的配色（Agent 自己写的，或用户给的整套色板），标准与生成时相同：`ink` ≥ 7:1、`muted` ≥ 4.5:1、`accent` ≥ 3:1、不落入排除区、图表按明度单调（浅底从深到浅，深底从浅到深）。

不合格时 `suggested` 给出改动最少的版本：色相只挪出排除区，对比度只调明度，图表只重排，没问题的角色不动。指定色在任何角色上都不改，要调就调底色，底色跟着平移面色。改不出来时（如两个指定色彼此对比度不够）`suggested` 为 `null`。
